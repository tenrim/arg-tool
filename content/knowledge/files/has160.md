## 介绍
<!-- sources: tta, code -->

HAS-160 是韩国 TTA 标准登记中的 160 位密码哈希。它将消息划分为 512 位块，链值由五个 32 位字组成。摘要长度与 SHA-1 相同，但消息解释和状态更新方式有明显区别。

## 小端字与补齐
<!-- sources: code, vectors -->

消息字节按小端解释。追加的 1 位以填充字节 80 开始，再补零并写入原始的 64 位小端位长。每个消息块的基础输入为十六个 32 位字。

:::example 单字节 a
[输入]
ASCII a，原字节为 61。
[结果]
4872bcbc4cd0f0a9dc7c2f7045e5b43b6c830db8
[说明]
第一数据字为 0x00008061，最后的长度字段值是 8。
:::

## 四个阶段的扩展与轮
<!-- sources: code, engine, vectors -->

压缩分四个阶段，每阶段二十步。其中用消息字的异或计算额外输入，各阶段有自己的字次序、常量和状态旋转方式。块末将工作字回加到原来的链值，完成逐块更新。

:::example 三字节向量
[输入]
ASCII abc，不带换行。
[结果]
975e810488cf2a3d49838478124afce4b1c78804
[说明]
原始三字节按小端置于第一个消息字的低三字节，紧接补位 80。
:::

## 状态输出
<!-- sources: code, engine, vectors -->

最后将五个链值字以小端顺序导出为 20 字节，十六进制展示占 40 个字符。空消息也要运行完整填充和压缩过程。

:::example 空消息向量
[输入]
零字节。
[结果]
307964ef34151d37c8047adec7ab50f4ff89762d
[说明]
首块只有补位和零长度域，结果仍有五个状态字。
:::

## 历史材料的算法名
<!-- sources: tta, code -->

旧协议若明确标注 HAS-160，应按其规定的字序与轮数核对。仅有 20 字节摘要时，可能还对应 SHA-0、SHA-1 或 RIPEMD-160 等算法，需要其他元数据或已知明文支持判断。

## 常见误区

- HAS-160 与 SHA-1 的字节顺序不同。
- 160 位意味着 20 字节，而非 160 字节。
- 自定义减少轮数的结果不能当作规范 HAS-160 向量。
