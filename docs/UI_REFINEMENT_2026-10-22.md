## 系统边界

共同外观与排版留在 `ui/components.css`，语义字号／间距补入既有主题变量，不迁移样式方案。页头操作的轻重由原按钮创建者声明；空状态可用性由原控制器同步更新。单位换算仍使用唯一 Qalculate 内核、原单位定义、原结果租约与完整导出，不增加换算倍率表。专题、导航、来源、实际工具数量不变。

新增的公共布局选项只表达 SplitView 子面板是否按内容高度排列，默认行为不变。科普继续使用同一全页阅读器，正文行长与示例／表格宽度分开处理。

## 用户反馈后的阅读宽度修正

用户指出 Base 家族正文只占左侧、右侧大面积空白，而示例仍铺满区域。根因是首次调整把 `35em` 限制直接施加到每个段落，错误地把“缩短行长”作为成功标准，没有核对其与全页阅读要求的冲突。不能以符合 skill 的行长建议代替用户的版式要求。

已在共享阅读组件移除段落／列表项的独立宽度上限，同时移除不再使用的主题变量。所有科普的正文、标题与示例均随同一个文章区域自适应，不逐页打补丁；保留本轮的字号和章节层级。

本次仅检查这次排版修正：1920px 的 Base 家族、1440px 的恩尼格玛，以及 375px／1.2 倍字号的 Base 家族。实际核对 92 个正文段落与 25 个示例边界，正文铺满所属章节、示例宽度一致，均无横向溢出，并查看宽屏与手机截图。记录在 `outputs/refactoring-ui-20261022/reader-width-fix/`，针对性脚本为同级 `verify-reader-width.mjs`。未重跑计算器、单位换算、历史记录或其他工具测试。
