# 2026-10-26 空间利用修复

用户指出上一轮仍有大量无用空间。本轮以前一轮修复后的实际界面为基线，调整结构和空态占位，保留新的前后对照。修改在本地工作区，未部署、提交或推送。

## 实施

- **转换参数流**：共享 ConversionLayout 的参数、方向和执行按钮使用同一条可换行布局。FormGrid 的显式 `layout:'flow'` 保留真实字段、标签与顺序；短参数不再拉满全行，完整编辑器保留整行，隐藏参数组不占位。摩斯识别参数卡在 1920px 下由约 376px 降至 169px。
- **输入区合并**：`native-workspaces` 将共享图片／音频／视频的原上传节点、文件信息和状态移入操作的输入卡片，离开时恢复原位置。移除空上传侧栏的占位，不复制文件输入或素材状态；输入来源已有标签，删除重复的“输入”小标题。真实文件、取消和结果失效仍由原所有者管理。
- **音乐工作区**：有足够容器宽度时，音色／八度／音量放在琴键旁；旋律录入和 MIDI 使用共享 SplitView 并排，中窄屏自然堆叠。BPM 等短数字字段保持适当宽度。乐器页三个工作卡片覆盖的主体区域由约 1399px 降至 749px，不含来源与站点页脚。
- **空结果与留白**：共享 Textarea 的最小高度遵从 `minRows`，转换结果和 MIDI 空输出保留两行，长内容仍增长至原上限并可滚动。MIDI 程序写入改用共享 `setTextareaValue`；空状态栏、空预览及段落叠加外边距不再占用多余位置。
- **来源排布**：完整项目、用途、许可及许可原文入口按可用宽度排列，兼容原列表和后挂载条目；单个项目保留可读宽度。没有删减、统一折叠或隐藏项目署名与许可内容。
