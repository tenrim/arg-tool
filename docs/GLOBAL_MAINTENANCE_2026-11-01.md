# 迷雾工具箱全仓检查与统一报告

检查日期：2026 年 11 月 1 日。产品仍为 V1.8。

## 这次检查了什么

这次清点约 5.08 万个文件，覆盖整个仓库，而不是只看主程序和笔记本。每个文件都进入分类清单并读取、计算摘要；第一方代码还进行格式、语法、模块关系与功能检查。第三方库保留原样，按固定来源核对，避免“统一格式”破坏引擎或许可。

| 范围 | 检查与处理 |
| --- | --- |
| 全部前端工具、共享组件和样式 | 统一格式；检查组件、路由、搜索、来源和功能回归 |
| 服务端 | 检查反馈与在线查询的独立边界、输入限制、取消和失败恢复 |
| 构建、导入与维护脚本 | JavaScript 与 Python 分别采用固定格式工具；检查生成器摘要和生成产物 |
| 测试与自动检查 | 清除机器专用浏览器路径，统一真实启动时序；补入此前漏登记的两组计算器回归 |
| 文档、部署配置和工具配置 | 检查目录、有效链接及现行规则；旧交互检查表归档，本机日志退出 Git |
| 第三方源码、运行包、字体、许可 | 逐个记录摘要；额外核对固定来源清单中的 28,849 个摘要和 151 项许可 |
| 本机 Android 原型 | 检查现有文件，14 项网络、录音生命周期与存储测试通过；保留原有未提交状态，不读取签名资料 |

逐文件记录保存在本机 `outputs/global-review/file-inventory.json`；可通过 `npm run audit:repository -- --report outputs/global-review/file-inventory.json` 重新生成。记录包含路径、分类、大小、摘要及实际检查项。第三方摘要记录不等于逐行审查所有上游算法。

## 已经解决的主要问题

1. **格式覆盖不再只限核心文件。** 全部第一方 JavaScript、维护脚本、测试和 CSS 都纳入统一规则；27 个 Python 脚本使用 Black。新增源码会自动进入对应范围。12 个 Python 脚本同时补齐显式 UTF-8 文本读写。
2. **修复真实界面缺陷。** 行程配速的“停留时间”输入与“停止”按钮原来使用同一 ID，已从公共计算表单修复；脑图在窗口变窄后中心主题可能跑出画布，现由引擎适配层处理尺寸变化，并在卸载时清理监听。
3. **把旧规则与当前实现对齐。** 文档明确两栏默认按内容高度排列，科普默认不进入关键词搜索，收藏保存具体工具，Desmos 是已批准的在线嵌入。对应回归改用真实控件、当前启动状态和实际依赖；计算结果、原始字节、取消、隐私、许可和键盘断言继续保留。
4. **检查入口覆盖全仓。** 新增全仓文件检查，前端和服务端合并检查依赖关系；CI 同时检查格式、文档和生成契约。完整验收登记增加普通计算器键盘和生活计算器，现有 82 组浏览器回归。
5. **文件分工有统一入口。** [开发指导](DEVELOPMENT_GUIDE.md) 是现行入口，[模块边界](MODULE_BOUNDARIES.md) 补齐服务、脚本、测试、工具、部署和历史资料的职责。历史说明只用于追溯，不再与新规则并列执行。

## 验证结果

| 检查 | 结果 |
| --- | --- |
| 项目单元测试 | 561 项；初次 559 项通过，两项过期计数／生成器摘要问题修复后对应测试通过 |
| 浏览器回归 | **82 / 82 组通过**；保留初次失败与各次复测记录 |
| 全局界面与使用说明 | 120 个工具路由、8 个网站路由；工作区回归覆盖 129 个页面及 320–1440px 宽度 |
| 语法与格式 | 全部第一方 JS／MJS 语法、统一 Prettier 范围、27 个 Python 脚本通过；3 个 PowerShell 脚本解析通过 |
| 格式改动的语义核对 | 376 个未作功能修改的运行模块语法树相同；40 个样式表、2,510 条浏览器规则等价；26 个既有 Python 脚本除显式编码外算法结构相同 |
| 文档 | 104 份 Markdown、486 个本地链接通过（含历史归档）；后续补充文字另做差异核对 |
| 来源与许可 | 28,849 个固定摘要、151 项许可通过 |
| 构建 | 完整静态站点生成成功 |

12 个 Python 维护脚本还修复了文本读写未指定编码的问题，统一显式 UTF-8，避免在 Windows 默认编码下损坏中文资料；对应资料测试及生成摘要通过。第一方代码与测试的改动都已找到明确检查归属，未登记的辅助脚本已补齐。本机代码检索因旧分类限制迁移到新索引；634 个源码文件全部接收，旧索引和参考库保留。

浏览器回归使用本机 Chrome 和隔离测试数据。在线查询的失败、取消与响应使用固定夹具；Desmos 核对本站嵌入入口和官方地址，不把这些检查称为第三方网站全部功能的在线验收。

前端与服务端共 377 个运行模块，字面量导入图未发现循环依赖。当前领域之间仍有明确登记的交接，例如图片结果进入笔记；这类必要联系不应为“零耦合”而复制数据库或算法。

## 以后怎样维护

普通修改继续只检查直接受影响的内容；只有明确要求全站验收时才跑完整检查。本轮是用户明确要求的全仓检查，不把它变成以后修改一个按钮也要跑全站的规定。

仍有较长的业务文件，例如功能登记、笔记控制器和在线资料适配；科普资料文件也很大。它们已经纳入本次检查，但文件长本身不等于职责错误。零循环依赖也不等于消除了所有维护成本。本次没有为了缩短行数而把同一事务或算法机械拆散。今后新增业务应继续在明确所有者内实现，避免重新扩大入口文件。
