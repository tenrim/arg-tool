# 当前部署与恢复说明

## 1Panel 的标准方式

- Node.js 24 或更新版本；项目目录指向仓库根目录，启动命令为 `npm start`。
- 保留当前端口、域名和 OpenResty 反向代理。网页、`/api/query/` 和 `/api/feedback` 必须转发到同一个网站运行环境，不转发到旧的独立端口。
- 在线查询只在玩家明确提交后访问固定来源，不依赖 SMTP。邮件由网站进程管理，只在回环地址启动内部服务，无需公开第二个端口。
- 保留服务器私密的 `services/feedback/.env` 和既有环境变量。配置不提交 Git，不写入 public 或 dist。字段、代理白名单、依赖自动准备见 [邮件服务说明](HANDOFF_FEEDBACK.md)；查询配置见 [在线查询说明](ONLINE_QUERY.md)。
- 不部署 AperiSolve 图片完整扫描服务，也不需要为该功能安装 Docker。

## 日常更新

1. 记录当前代码版本和运行环境配置，确认服务器没有未备份的本地代码修改。
2. 正常同步目标分支，保留私密配置。不要用强制重置或清理未跟踪文件代替同步。
3. 重启原来的运行环境。邮件依赖只有缺失或锁文件变化时自动准备。
4. 确认网站能打开，做一次本地 Base64 转换；主动提交一条公开数列，确认查询正常。上游超时或限流应明确提示，不能影响本地工具。
5. 查看启动日志中的反馈状态。`FEEDBACK_READY` 只说明本地服务就绪，不证明邮件已投递；`npm --prefix services/feedback run verify-mail` 检查 SMTP 连接和登录，不发送邮件。真实投递验证须明确授权后另发测试邮件。

只交付纯静态网站时才使用 `npm run build` 生成 dist。纯静态文件不会启动上述后端，不能用更新 dist 代替重启运行环境。

## 更新异常时恢复

- 保留错误日志、当前版本标识和配置，不删除浏览器笔记或重建数据库。
- 使用更新前记录的代码版本恢复应用并重启，保留私密配置；确认该版本支持当前数据格式。
- 本轮笔记 IndexedDB 升级到版本 2，原 notes 数据保留并原子生成摘要索引。旧页面持有数据库时需关闭后重试。
- 升级后不能直接回退到仅支持 IndexedDB 版本 1 的笔记代码，旧代码无法打开较新的库。应先通过当前版本导出完整备份，再使用兼容版本，不通过清空站点数据解决版本冲突。
- 笔记在玩家浏览器、当前网站源内，服务器代码备份不等于笔记备份。域名、协议或端口变化前应提醒玩家导出完整备份。

## V1.0 发布前的针对性验收

核对本轮受影响测试报告；在实际部署环境另行确认查询连通、邮件登录、静态组件地址和重启行为。上游结果或真实邮件投递不能由本地模拟测试代替。真实设备上的大容量笔记与低内存承载量须单独说明，不把桌面浏览器回归当作所有设备保证。
