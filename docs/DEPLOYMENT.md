# 当前部署与恢复说明

## 1Panel 的标准方式

- Node.js 24 或更新版本；项目目录指向仓库根目录，启动命令为 `npm start`。
- 保留当前端口、域名和 OpenResty 反向代理。网页、`/api/query/` 和 `/api/feedback` 必须转发到同一个网站运行环境，不转发到旧的独立端口。
- 在线查询只在玩家明确提交后访问固定来源，不依赖 SMTP。邮件由网站进程管理，只在回环地址启动内部服务，无需公开第二个端口。
- 保留服务器私密的 `services/feedback/.env` 和既有环境变量。配置不提交 Git，不写入 public 或 dist。字段、代理白名单、依赖自动准备见 [邮件服务说明](HANDOFF_FEEDBACK.md)；查询配置见 [在线查询说明](ONLINE_QUERY.md)。
- 不部署 AperiSolve 网站及自动完整扫描。2026-11-03 起，用户授权的独立文件分析工具使用隔离 Docker 容器，按点击运行单项；构建、启用和本地验证见 [独立分析工具](FORENSICS.md)。

代码运行的新增服务器语言采用独立、默认关闭的隔离服务。只有完成 [代码运行扩展](CODE_RUNNER.md) 的镜像、原始许可及真实运行验收后才可设置 CODE_RUNNER_ENABLED=1；同源反向代理另转发 `/api/code/run`。本轮开发不自动授权生产部署。

## V2.0 隔离服务部署

2026-11-04 用户授权发布 V2.0，并在验收后清理本项目的多余部署缓存。保留原 `arg-tool` 网站容器、端口、邮件和查询配置。新增 `mist-tool-sandbox` 网关，入口为 `services/sandbox/start.mjs`，只组合既有文件分析和代码执行服务，不复制校验、限流、任务状态或执行逻辑。

网关使用现有 Node 25 镜像、只读根文件系统及只读源码挂载，监听宿主回环 `127.0.0.1:3215`。它作为可信容器调度器使用 Docker CLI 和 socket；玩家代码和文件只进入原有禁网、非 root、限额任务容器，不获得 socket、网关环境或网站私密配置。不能把调度器本身当成不可信任务运行容器。

OpenResty 仅将 `/api/forensics/run` 和 `/api/code/run` 两个精确路径转到网关，分别设置 28 MB／4 MB（文件内容仍限 20 MB，28 MB 用于 Base64 与 JSON 包装） 请求上限及 270／125 秒读取超时。关闭这两条路径的请求和响应代理缓冲，避免把上传文件、密码和代码落到代理临时文件；断连取消仍由原服务处理。其余路径保持原网站上游。

发布固定使用已实测镜像 ID：文件分析 `sha256:030b69297c9f1043fd0127131ba2f8082b90e02827ed0bcfd77c53a344e64c20`；代码执行 `sha256:7ce4b43845397f947a970938eb38bc6a10f55ebcf6715e98fd3ebe126a66689b`。不重新下载编译器，不执行全局 Docker prune，不删除数据库卷或其他站点镜像。

差异文件逐项记录原／新 SHA-256，原文件与代理配置保存到本次发布备份。清理只针对已确认属于工具箱的旧构建容器、失效镜像、上传包和旧发布备份；保留当前服务镜像及本次发布前的直接回滚备份。具体发布结果、清理清单和回滚步骤记录在 [V2.0 发布记录](releases/V2.0-发布记录.md)。

## 日常更新

1. 记录当前代码版本和运行环境配置，确认服务器没有未备份的本地代码修改。
2. 正常同步目标分支，保留私密配置。不要用强制重置或清理未跟踪文件代替同步。
3. 重启原来的运行环境。邮件依赖只有缺失或锁文件变化时自动准备。
4. 确认网站能打开，做一次本地 Base64 转换；主动提交一条公开数列，确认查询正常。上游超时或限流应明确提示，不能影响本地工具。
5. 查看启动日志中的反馈状态。`FEEDBACK_READY` 只说明本地服务就绪，不证明邮件已投递；`npm --prefix services/feedback run verify-mail` 检查 SMTP 连接和登录，不发送邮件。真实投递验证须明确授权后另发测试邮件。

只交付纯静态网站时才使用 `npm run build` 生成 dist。纯静态文件不会启动上述后端，不能用更新 dist 代替重启运行环境。

## 更新异常时恢复

- 保留错误日志、当前版本标识和配置，不删除浏览器笔记或重建数据库。
- 使用更新前记录的代码版本恢复应用并重启，保留私密配置；确认该版本支持当前数据格式。
- V1.8 笔记 IndexedDB 升级到版本 3，在同一数据库增加素材存储，保留 notes 与摘要索引；更早版本仍执行所需升级。旧页面持有数据库时需关闭后重试。
- 升级后不能直接回退到仅支持 IndexedDB 版本 1 或 2 的笔记代码，旧代码无法打开较新的库。应先通过当前版本导出完整备份，再使用兼容版本，不通过清空站点数据解决版本冲突。服务器文件回滚不代表浏览器数据库可以降级。
- 笔记在玩家浏览器、当前网站源内，服务器代码备份不等于笔记备份。域名、协议或端口变化前应提醒玩家导出完整备份。

## V1.0 发布前的针对性验收

核对本轮受影响测试报告；在实际部署环境另行确认查询连通、邮件登录、静态组件地址和重启行为。上游结果或真实邮件投递不能由本地模拟测试代替。真实设备上的大容量笔记与低内存承载量须单独说明，不把桌面浏览器回归当作所有设备保证。
