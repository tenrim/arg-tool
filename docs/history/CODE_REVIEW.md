## 归档复核：发布前删减与双端操作（2026-10-08）

桌面问题是任务输入/结果被大块选择区域挤到下方，以及上传、媒体预览、参数占据整行。1100px 以上改为功能侧栏与任务、播放器与分析、画布与参数并排；移动端保持阅读顺序和至少 44px 的碎片主要操作按钮。代码运行按钮移到编辑框前，避免需要穿过整个编辑框才能运行。

20 项既有完整回归加 1 项发布专项通过，40 个 Node 用例通过；117 个 npm 包名暂无已知公告。另提供 static ZIP、文件摘要、1Panel 新建站点指南和 OpenResty 配置片段；不把缺失的运行包重写成 HTML、不长期缓存无版本文件。服务器尚未创建且未连接，真实服务器配置与证书需要按部署说明最终验收。

## 2026-10-08 后续修复：本地运行说明与处理链边界

- 页脚明确本站常规工具的输入、文件和结果在浏览器本地处理，不上传或存于本站服务器；原页展开说明网页资源加载、主动 HTTP/DNS、外部服务、本机草稿与托管访问日志的区别。检查手机换行和 200% 字号。
- 处理链新文件加载时立即丢弃旧文件输入并禁用执行；编辑文字或清空会使晚到的读取失效。文件读取代号与配方编辑独立，避免调整参数误取消文件读取。
- 配方导入使用独立序号，较晚完成的导入不覆盖较新的编辑；忽略格式损坏的本机存储条目，保留有效配方。
- 共享 CyberChef 客户端校验 UTF-8 输入、实际输出和多文件总量上限；超限输出关闭 Worker，清理保留的响应。限额不等于引擎分配之前的硬内存隔离。
- 修复官方 `OperationError` / `DishError` 可能返回 `error=false` 导致“错误结果显示成功”：客户端同时检查处理链执行进度；正常流程控制、停用步骤不误报。
- 重新确认 Remove EXIF 的根因是无 EXIF / 空输入分支返回 Uint8Array，但声明输出为普通 byteArray。本站 Worker 类型适配仅统一该返回值，官方引擎和 Image 模块原字节未改。含 EXIF 的 JPEG 移除后与原无标签 JPEG 逐字节一致；无 EXIF / 空输入保持原样，非法 JPEG 报错。图片页直接入口恢复，目录现为 489 任务 / 1 现有入口 / 10 流程控制 / 5 保留项。
