## 逐项依据与接入边界

### E01 OEIS

**结论：A 公开接口可接。** 已经接入，可作为同页在线查询的基准。

- **接口或实现方法：** 官方 /search?q=…&start=…&fmt=json，本站仅转发明确提交的查询。
- **可以返回的内容：** 本页完整原始记录、定义、数列项、offset、公式、注释、程序、作者、文献和原条目链接；JSON 返回不等于条目另附 b-file 的全部数列项。
- **账号、费用与限额：** 无需用户账号或付费 Key。现有本站策略为全服务每 10 秒最多一次，并设逐地址限流；这不是上游承诺的配额。
- **许可与署名：** OEIS 数据 CC BY-SA 4.0，保留基金会、贡献者、条目链接与许可。不能将接口可用描述为允许后台整库抓取。
- **实现难度：** 已完成
- **本次核实状态：** 2026-10-17 已用公开 A000045 经本站后端实际查询成功，并检查完整笔记记录。
- **建议处理：** 保留现有查询、完整保存和联网提示，不恢复旧精选库。
- **官方依据：** [OEIS JSON Format](https://oeis.org/wiki/JSON_Format)；[OEIS End-User License](https://oeis.org/wiki/The_OEIS_End-User_License_Agreement)。

### E02 FactorDB

## 实施时必须保留的边界

1. 每个来源使用自己的适配器、固定目的地、参数白名单和结果模型；不能把当前 OEIS 模块改成接受任意 URL 的抓取代理。TAP、晶体、词语和任务队列不共用一份假定字段。
2. 查询内容本身也可能是未公开线索。点击查询前明确目的地；默认不发送文件、笔记、其他输入或 Cookie。图片/音频上传单独提示上游保存、公开和删除规则。
3. 服务限流、计费和配额按来源分别管理。遇到 403、429、登录、验证码或服务故障，给出可理解的失败与原站入口，不绕过、不静默换源、不无限重试。
4. 完整保存所声明返回的结果、ID、字段单位、查询条件、来源、时间及必要许可。原站未返回总数时不虚构；超大字段、分页、截断与未展开结果要明确。不能用少量样本代替原站完整检索用途。
5. 笔记保存/导出按来源许可分别决定。开放 API 不自动允许永久缓存、复制图片或分享完整正文；对于商业地图等受限内容，可仅保存原始线索、自写笔记和许可允许的标识/链接。
6. 接入完成时同步补齐实际任务页脚、关于页、来源与许可记录、故障提示；仅保留外链的站点不列成已集成依赖。沿用单个 `npm start` 管理轻量查询适配器，自建扫描栈属于额外部署项目。
