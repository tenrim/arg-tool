# 新版 Refactoring UI 复查

## 页面切换动画修正

用户随后报告本地环境切换功能时动画不一致。实际记录表明：跨面板切换有 ToolPanel 整体进入，共用面板的元素表／摩尔质量／分子结构切换却只启动部分卡片。首次和重复进入都存在差异，并非浏览器资源缓存失效。另有导航自动设置参数的合成 input 事件被共享动效误当成连续输入，导致整体进入被短暂抑制。

已由路由在同面板真实视图完成选择后调用共享进入动画，保持页根只淡入；共享动效接管子级已启动的效果，避免叠加。导航初始化事件声明来源，使其与真实连续输入区分，原控制器仍收到全部 change/input，不改变参数、取消或结果失效行为。

本次仅执行 `outputs/trace-workspace-motion.mjs verified`，记录在 `outputs/workspace-motion-verified.json`：四个代表功能的八次首次／重复切换均出现工作区整体动画；连续输入仍抑制进入，外层接管后没有子级残余动画，页根没有位移／变换，动态启用减少动态后取消并保持安静，原分子式输入保留。对照记录在同级 `before`、`after`、`corrected` JSON 中，未运行全站动效或化学引擎套件。

### 后续用户纠正：保留明确进入效果，优先 Animate UI

上一次统一成整页淡入并未满足用户要求。本次使用已锁定的 Animate UI 2.0.0 `Effect` 真实原语，组合滑入与淡入；原始节点由局部 NativeHost 适配，不迁移工具状态。页面根不位移，固定／粘性容器保留位置，其安全标题及控件仍可滑入。路由等待真实控制器准备完成才触发进入，避免慢加载时动画提前播完。

实际执行 `outputs/verify-animate-ui-entry.mjs` 与 `outputs/verify-animate-ui-entry-guards.mjs`。六次跨页／共用容器／重复进入均采样到位移与透明度变化，最大位移 16px、透明度从 0 到 1；手机触控位移不超过 8px。中断从当前绘制位置继续，固定测试元素始终位于视口 (1200,80)，输入原节点、焦点和已选文件保留，真实输入抑制仍正常；网站减少动态设置能立即停止，并在恢复后重新播放。页面根一直无 transform。

Chrome 测试环境的动态媒体模拟未派发所等待的媒体变更事件，该路径没有计为通过；改用网站真实动态设置验证即时取消与恢复，没有降低取消断言。另修正了测试夹具自身未静止、Document 合成点击产生的无效测试条件。最新记录在 `outputs/animate-ui-entry/checks.json`、`guards.json`，效果录屏为同目录 `page-entry-demo.webm`。未重跑其他工具或全站套件。

由项目原构建器重新生成 UI 运行包，依赖版本和 lockfile 未变。实现来源、全局页脚、关于页用途、notice 与 UPSTREAM 摘要同步更新。用户要求的 Animate UI 优先规则已写入全局记忆增量，同时同步项目 UI 规范。

### 后续卡顿修正：过渡参数、准备阶段与旧渲染清理

本次重新记录维吉尼亚、Nihilist、埃特巴什三项工具的首次／重复进入，并采集 CPU 调用栈。没有复用上节的历史通过结果。发现 `controls.start()` 的 delay-only 参数会整体替换 Effect 的默认过渡，导致 Animate UI 弹簧被 Motion 默认补间取代；主区域还被人为分成最多 96ms 的分批进入。现使用原包 `motionTokens.spring.entrance`，同次导航一起进入；重复调用沿用当前运动值，不在接近终点时重置到起点。

共享动效批次先合并重叠子树、去重悬停组和选择器，再挂载原生控件适配；隐藏集合直接跳过几何测量。进入效果先设置初态与临时合成提示，让布局和尺寸观察器完成准备后开始插值，不延迟控制器、焦点和取消。取消／完成时同时清理已排队的末尾渲染，避免旧透明度和变换写回；取消及后续播放均受同一代次保护。错误报告观察器原来因控件 class／子节点变化扫描全部工作区，现只检查变动状态和新增子树，保留错误报告入口。

本轮执行：`outputs/profile-entry-stutter.mjs`（正常采样关闭 CPU profiler）、`outputs/verify-entry-stutter.mjs`、`outputs/verify-animate-ui-entry-guards.mjs`，以及三个源码文件的语法与差异空白检查。最终六次采样中，Nihilist、埃特巴什和再次进入的动画播放段最大帧间隔为 16.8–16.9ms，主要卡片无旧分批错位；首次维吉尼亚仍有一次 50ms 的播放长帧。导航准备阶段仍记录到部分长任务，因此不宣称所有首次加载开销已经消除，也不把播放帧间隔当成整次导航耗时。

针对性断言通过：真实报错新增／更新／清空／恢复／移除、嵌套选择器只挂载一份、首帧前取消、实际工具快速连续切换、固定元素坐标、原输入／文件／焦点保留、连续输入抑制、网站减少动态即时取消与恢复、375px 触控进入。记录为 `outputs/entry-stutter-final.json`、`outputs/entry-stutter-checks.json` 和本轮更新的 `outputs/animate-ui-entry/guards.json`。最初新增的取消用例发现 Motion 排队末帧会写回 `opacity:1 / transform:none`，已修正并重跑相关用例；未删除该清理断言。没有全站测试、构建、部署或 Git 提交。

另执行 `outputs/verify-entry-lightweight.mjs`，只读取动画内联值、不读取布局；首次维吉尼亚仍采到约 50.1ms 的播放长帧，记录在 `outputs/entry-stutter-lightweight.json`。因此不能将剩余长帧归咎于诊断脚本，也不能据此宣称首次进入完全无卡顿。
