# 本轮最小必要验证

2026-10-21 按用户要求更新。本规范替代旧版“先跑计划再执行其全部检查”“共享组件检查所有使用方”“最小只能执行整套测试”等要求。其他文档和历史报告列出的全套覆盖是保留的测试能力，不是日常任务清单。

## 范围和停止条件

1. 只审查本轮实际修改的内容，验证改变的行为及有具体依赖证据的直接影响。不把工作区其他未提交改动、历史功能或无关模块带入本轮。
2. 测试数量与改动相称。文档、文案、标签、简单排列和可逆样式调整通常只需差异检查或针对性查看；不强制测试计划、浏览器套件、全站构建或架构审计。
3. 功能修改优先运行具体用例；共享组件修改只验证改变的契约和少量代表性直接使用方。不得仅因文件是公共文件、被多个模块引用或自动计划选中了某套件，就遍历全部页面、引擎或使用方。
4. 相关验证通过后直接交付。已通过且此后未受新改动影响的检查不重复；失败后仅重跑失败项和修复直接影响项。
5. 只有具体关联故障、明确依赖证据或用户明确要求时才扩大范围，并简述原因。保留完整测试库、安全边界和真实行为断言，不能为缩短执行而删除断言、隐藏错误或伪造通过。

## 按行为选择检查

| 本轮改动 | 最小必要验证 | 不自动连带 |
| --- | --- | --- |
| 文档、文案、帮助、标签 | 修改片段、受改链接或一次对应页面查看 | 浏览器套件、架构审计、构建 |
| 单页按键筛选、排序、简单样式 | 对应按键／排序／布局；存在切换状态时核对该状态 | 其他工具、全站导航、多页面遍历 |
| 共享组件布局或动效 | 改变的组件契约、代表性直接使用方及必要视口／动态场景 | 全部使用方、所有视口与无关引擎 |
| 路由、任务身份、偏好 | 被修改的路由或状态流及直接调用方 | 全部工具算法和完整页面巡检 |
| 分类、能力或来源元数据 | 变动条目的归属、别名、对应展示；全局不变量改变时检查该不变量 | 所有任务的实际运算 |
| 算法、资料模型 | 对应真实输出和受改边界 | 无关 UI、其他算法 |
| Worker、资源适配、固定运行包 | 所属实际引擎及本轮涉及的加载／失败／取消行为 | 其他独立 Worker |
| 来源许可文案 | 变动记录、路径和对应展示 | 全站许可证浏览器巡检 |
| 模块导入、跨模块桥接 | 改变的依赖边和直接联动行为 | 与此边无关的架构或引擎检查 |
| 生成、打包、交付产物 | 受影响生成物／构建／打包结果 | 默认全量测试 |

PC／手机、键盘、正常／减少动态、跨任务失效等覆盖继续保留。仅在本轮行为涉及这些差异时选取必要场景，不把完整覆盖矩阵套到每个改动上。计算逻辑改动验证实际输出，不能只检查页面存在。

## 自动计划是候选清单

需要辅助定位测试时，可使用：

```bash
npm run test:plan -- --files public/round1/braille.js
```

`--files` 列全本轮修改文件，不能少报路径来规避相关检查。大范围清单可用 JSON 字符串数组及 `--files @docs/本轮文件.json`。重命名同时列旧、新路径。分支／CI 比较才按该任务使用 `--base`；日常不要无参数运行 `verify`，其默认会收集暂存、未暂存和新增文件，混入以前的工作。

逐项核对计划的触发原因。只有候选检查均与本轮直接相关、粒度合适时，才执行相同文件范围的 `npm run verify -- --files ...`。不能因为自动选中了 14 项就机械跑完 14 项。

计划过宽时，直接运行相关测试文件、受支持的用例筛选或针对性页面验证。例如 Node 单元测试可使用 `node --test --test-name-pattern='用例名称' tests/对应文件.test.mjs`；浏览器脚本只能使用其实际支持的筛选方式，不能编造参数或声称已执行未运行的用例。现有某些浏览器脚本只能整套执行：这不构成扩大验证的理由，改用可复现的针对性验证；经常需要筛选时再在相关任务中完善脚本粒度。保留原完整套件及断言。

`npm test` 选择单元检查，`npm run check` 选择静态检查，`verify` 已包含二者，不再依次重复执行。普通文档与 UI 修改不生成 dist；浏览器可直接读取 public。只有生成、打包或本次交付产物受影响时才构建。完整入口 `test:all`、`check:all`、`verify:all` 保留给明确的全量任务，发布也不自动意味着全站验收。

## 映射、固定来源与 CI

`scripts/test-map.mjs` 维护浏览器套件及文件职责，`affected-plan.mjs` 根据 Git、依赖及显式映射产生候选清单。它们只能辅助定位，不能代替行为范围判断；公共帮助、来源、许可、装配文件的依赖扩散不等于所有下游都要运行。自动计划与 CI 当前仍按现有映射执行，本文不宣称脚本已支持逐用例筛选。

新增代码必须有明确的行为所有者和适当的验证方式；未知路径不能静默当作通过，也不能兜底运行全套。新增有必要的持久回归时登记到对应映射和完整目录，不为低风险改动增加复刻实现的测试。

修改固定来源或生成器时只核对受影响来源的完整性及对应产物；联网导入、维护编译须按对应维护文档执行，测试不得擅自更新固定来源。职责与运行时桥接规则见 [MODULE_BOUNDARIES.md](MODULE_BOUNDARIES.md)，只在相关依赖变化时查阅对应部分。

GitHub PR／push 按对应基线比较，手动 full 保留为明确全量入口；Gitee 当前没有对应云端流水线。CI 的实际执行范围和成功状态以运行记录为准，既有 CI 配置不能成为本地重复或扩大验证的理由。需要调整映射或流水线时，将其作为明确改动并验证其自身行为。
