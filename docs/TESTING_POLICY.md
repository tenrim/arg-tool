# 按变更选择验证

2026-10-13 起按用户要求替代“共享代码一改就全量验证”的流程。保留所有原有行为、安全、许可断言，改变执行范围，不降低断言。

## 日常命令

```bash
# 查看本轮计划和每项触发原因
npm run test:plan -- --files public/capabilities/sidebar.js
# 执行相同范围（静态 + 必要单元 + 对应浏览器）
npm run verify -- --files public/capabilities/sidebar.js
# 未指定文件：包含暂存、未暂存、新增和删除；分支比较可加 --base main
npm run verify -- --base main --report /tmp/arg-affected.json
# 只有明确需要整站验收时才运行
npm run verify:all -- --report /tmp/arg-full.json
```

`--files` 必须列全本轮实际修改的文件。工作区含之前已经验证的改动时，用它隔离本轮范围，避免每轮重复跑旧改动。不要通过少报文件跳过实际受影响的检查。重命名按旧、新两个路径识别；找不到 Git 基线、缺少测试或存在未登记代码时明确失败，不静默通过。

`npm test` 只跑受影响单元，`npm run check` 只跑受影响静态检查。`verify` 已包含两者，不要再顺序重复执行。`test:all`、`check:all`、`verify:all` 保留显式完整入口。普通修改不自动构建 dist；只有生成器、打包逻辑或本次需要交付 dist 时才构建。浏览器回归直接读取 public，因此本地调试不需要为了测试重复复制整站。

## 选择依据

`scripts/test-map.mjs` 是浏览器套件及文件职责映射的唯一维护入口；`affected-plan.mjs` 处理 Git、单元依赖、审计和生成器的依赖顺序。报告保留文件、检查、触发原因和实际执行结果。

| 变更 | 选取的行为 | 不自动连带 |
| --- | --- | --- |
| 侧栏、纯路由序列化 | 侧栏直达、方向、手机、键盘、输入保留 | 天文、音视频、解释器引擎 |
| 分类与功能登记 | 来源覆盖、别名、发现与侧栏 | 各算法的完整运行回归 |
| 组件外观、布局、动效 | 对应组件／布局／动效专项 | 所有工具引擎 |
| 科学算法、资料模型 | 对应单元实际输出和边界 | 无关工具 UI |
| Worker、资源适配、固定运行包 | 所属实际浏览器引擎及错误恢复 | 其他独立 Worker |
| 资料到天文、CIF 到模型的桥接 | 两端的真实对象与失效契约 | 全站工具 |
| 许可、来源 | 完整性、来源展示专项 | 所有计算结果 |
| 文档 | 文档链接 | 浏览器、生成器、打包 |

单元测试通过真实字面量 import／re-export 依赖补充选择；测试中导入页面的纯校验函数，不因此把 UI 入口的全部依赖当作算法测试对象。浏览器选择以行为所有权为准，不沿 app.js 的装配依赖扩散到所有工具。CSS、事件、计算生成的 Worker 地址不适合仅靠 import 图推断，使用显式映射与桥接记录。

选中的测试内部仍保留正常／减少动态、PC／手机、键盘及真实引擎断言，不通过删用例来缩短时间。现有某些套件包含同领域多个工具；目前最小执行单位是一个套件，不声称达到每个断言的精准筛选。

固定上游／生成器相关变更先核对完整性。只自动执行命中的离线 JS 生成器；联网导入、Rust/Python 维护编译须按对应维护文档显式执行，不能由测试命令擅自更新固定来源。未知文件要求补测试归属，不能自动兜底全套，也不能当作无须检查。

## 失败与 CI

默认遇首个失败停止，报告剩余未执行项；修复后仅重跑失败项及修复新增影响范围，已通过且未受新修改影响的检查不重复。不能将未运行、仅计划或历史通过写成当前通过。

GitHub PR 使用与目标分支的共同祖先，push 使用前一个提交基线；差异有浏览器测试才安装浏览器工具。`workflow_dispatch` 的 full 是主动完整验收入口。Gitee 没有对应云端流水线，当前规则由本地执行。CI 配置变化已在仓库落地，云端是否成功须看实际运行。

## 维护验证体系

新增页面／源目录必须登记行为归属；新单元测试会自动发现，新浏览器套件需加入统一目录及映射。`tests/testing-policy.test.mjs` 验证不扩散、未知文件报错、Git 各种状态、完整套件保留；`tests/architecture.test.mjs` 验证代码边界、路由兼容和元数据共享。

本流程不会把静态扫描冒充完整语义分析。职责、运行时桥接和已知集中点见 [MODULE_BOUNDARIES.md](MODULE_BOUNDARIES.md)。
