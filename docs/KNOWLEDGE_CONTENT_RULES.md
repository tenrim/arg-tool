# 逐功能科普内容规则

用户要求具体到每种编解码／功能，明确否定按大主题泛讲的科普。这个约定覆盖旧版“每个工具组一篇”的实现。

## 覆盖与粒度

- 每项可见 capability 一个独立 article，`id = function-<capabilityId>`，`capabilityIds` 只含对应功能。已有编码／解码、加密／解密功能族是一篇，不能拆成两篇或另列一套配对表。
- 标题只使用基本功能名，如 Base64、六点盲文、SSTV；不能追加解释性后缀、问题或重复双向名称。目录按钮只显示名称，阅读页不再追加概述或分组标签；机制与例子在正文展开。旧分组科普及其兼容入口按用户要求删除，不做转跳或隐藏保留。
- 一篇说明该功能是什么，输入按什么单位处理，怎样排列、映射或运算，具体例子如何得出结果，哪些参数和边界会改变结果。不能从菜单名称自动套出泛文。资料条目说明具体代码体系、字段或读法，模拟条目说明实际规则。
- 不用“同属一组”建立学习关联；登记依据精确 capability ID。新增可见功能必须同时有独立科普，否则 `createRegistry` 拒绝构建。

## 资料依据

- 先检索并阅读标准制定机构、政府、高校官方课程、正式厂商文档、维护者规范。社区文章、转载、百科和搜索摘要不能作为权威断言的唯一证据。
- 国内官方中文资料优先；原始标准有国内高校镜像时优先提供可读镜像。无法找到中文权威版本时标明原文语言，不冒称中文，不强贴不相关的国内链接。未在国内真实网络测试的链接不声称已通过运营商测试。
- 每个正文小节的 `sourceIds` 精确引用本篇 `sources`。来源记录标题、机构、实际地址、资料性质、语言和章节。引用必须直接支持该节的规则与实例，不能在文章末尾堆一批泛链接充数。
- 项目自定义编码必须引用实际作者规则，必要时核对固定版本的实现。本站 CyberChef 固定版本及本地 catalogue 只证明对应操作的实际参数／行为，不意味着一种规则是国家或国际标准。公开标准与实现差异必须明说。
- 使用基于原始资料的中文释读和可核算例子，避免复制整篇资料。若复制许可允许的第三方文字、数据、图像，记录实际许可和署名；原引擎的上游通知保持完整。

## 模型与界面

`public/knowledge/articles/*.js` 保存逐功能内容，`content.js` 校验并冻结；分类仍由 `navigation.js` 与能力登记派生。每节至少有明确规则和相应资料，全篇至少有一个可核对的输入／输出或结构演算。无来源、无实例、重复／缺少功能、无效关联或危险 URL 直接报错。

公共 `ReferenceList` 通过 `ui/index.js` 使用，外观由组件样式统一拥有，将文献放在对应段落和例子旁。它显示机构、章节、资料语言，使用安全链接与可访问名称。文献不是软件依赖，不虚构项目来源页脚。目录仍支持领域、主题和正文搜索，手机／桌面保持已有组件与焦点约定。

## 审核与回归

确认引用页面确实有相应内容，分别核验标准事实与本站行为。保留实际阅读证据和未能访问的限制，不把 HTTP 成功或搜索摘要当作全文审核。测试从统一登记检查逐功能覆盖、双向家族唯一性、工具与科普精确联动、来源绑定、安全链接、简洁功能名称及旧科普已移除；核验 Base64 分组／填充、盲文点位、SSTV 音调／扫描规则等具体例子。

浏览器验证逐篇正文与旁注确实渲染、真实关联工具可打开、输入保留、阅读焦点、普通／减少动态效果，以及 320／390／800／1440px 和 200% 字号的阅读与链接布局。公共组件改变仍需完整 `npm run verify`，不能仅检查文章菜单存在。

## 国内可读的原始实现资料

`vendor/knowledge/UPSTREAM.json` 固定逐文件 SHA-256，独立于实际运行库。`scripts/import-knowledge-sources.py` 是联网维护入口，仅复制已引用的固定 CyberChef 源码和已收录解释器作者文档，不替换原运算文件；原字节、作者头、Apache-2.0／MIT 原文与原始地址全部保留。正文的本地引用保留上游地址及许可证，公共 ReferenceList 显示站内原文、上游链接和实际许可；子目录部署从资源根解析。普通 check／build／verify 只离线核对摘要。

本轮资料与只读独立检查记录见 [复核目录](knowledge-review/README.md)，获取限制与问题发现快照保留；最终处置及完整运行以 CODE_REVIEW.md／VERIFICATION.md 为准。

公共 Worker 操作修正已纳入 `browser-chef-corrections`：位提取列序、TCP/IP进位、完整字节卡方求和、AMF3节点、AMF0UTF8长度与AMF按长度保留内嵌NUL。修正保留官方vendor字节，独立任务与处理链行为一致；AMF仅在固定模块同步导入时捕获经过严格结构验证的类型，finally恢复全局函数，继续使用原序列化器与解码字段树。不得在UI伪造成功结果。
