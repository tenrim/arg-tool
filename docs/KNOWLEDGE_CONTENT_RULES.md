# 逐功能科普内容规则

用户要求具体到每种编解码／功能，明确否定按大主题泛讲的科普。2026-10-16 新批准同用途专题工作区：一个专题一个科普入口，但每个成员的具体内容必须完整保留；这不恢复旧版“每个工具组一篇”泛概论。

## 文体（用户确认于 2026-10-22）

- 科普采用客观的知识条目文体，使用 [Weijinchen 版 humanizer-zh](https://github.com/Weijinchen/humanizer-zh/blob/main/SKILL.md) 的教材模式。小节使用“介绍”“结构与工作原理”“参数”等中性名称，正文直接说明概念、条件和过程，避免设问式标题、与读者闲聊、动员性语句和评价性旁白。
- 文风改写保留事实、术语、参数、演算结果与引用归属；不能以精简措辞为由删去必要条件和适用范围。参考资料仍集中放在文章末尾。

## 覆盖与粒度

- 每项可见 capability 一个独立 article，`id = function-<capabilityId>`，`capabilityIds` 只含对应功能。已有编码／解码、加密／解密功能族是一篇；真实配对只在 `capabilities/operation-pairs.js` 定义，不能在科普中复制或推测逆向关系。
- 同用途专题只显示一个文章入口，`knowledge/topics.js` 从其实际成员内容做纯投影。逐成员保留准确的机制、输入单位、运算／映射步骤、完整可复核实例、参数和边界，不能只把各成员名称列出来或删成一段简介。专题同属不等于算法可逆；签名／验签、哈希或有损处理不能被科普合并误称逆向。
- 标题只使用基本功能／专题名，如 Base64、PGP 工具、信息提取、六点盲文、SSTV；不能追加解释性后缀、问题或重复双向名称。目录按钮只显示名称，阅读页不再追加概述或分组标签；机制与例子在正文展开。旧泛分组科普仍不恢复，专题成员须精确对应已登记的 `actions`／`variants`。
- 一篇说明该功能是什么，输入按什么单位处理，怎样排列、映射或运算，具体例子如何得出结果，哪些参数和边界会改变结果。不能从菜单名称自动套出泛文。资料条目说明具体代码体系、字段或读法，模拟条目说明实际规则。
- 不用“同属一组”建立学习关联；登记依据精确 capability ID。新增可见功能必须同时有独立科普，否则 `createRegistry` 拒绝构建。
- 新增 78 个配方专用 CyberChef 操作不再各登记独立文章；原 10 个流程控制仍在完整处理链文章解释。其原始配方操作、参数、执行和 505 项来源覆盖保留，不能为了科普计数重新生成独立工具入口。

## 资料依据

- 先检索并阅读标准制定机构、政府、高校官方课程、正式厂商文档、维护者规范。社区文章、转载、百科和搜索摘要不能作为权威断言的唯一证据。
- 国内官方中文资料优先；原始标准有国内高校镜像时优先提供可读镜像。无法找到中文权威版本时标明原文语言，不冒称中文，不强贴不相关的国内链接。未在国内真实网络测试的链接不声称已通过运营商测试。
- 每个正文小节的 `sourceIds` 精确引用本篇 `sources`。来源记录标题、机构、实际地址、资料性质、语言和章节。引用必须直接支持该节的规则与实例，不能在文章末尾堆一批泛链接充数。
- 项目自定义编码必须引用实际作者规则，必要时核对固定版本的实现。本站 CyberChef 固定版本及本地 catalogue 只证明对应操作的实际参数／行为，不意味着一种规则是国家或国际标准。公开标准与实现差异必须明说。
- 使用基于原始资料的中文释读和可核算例子，避免复制整篇资料。若复制许可允许的第三方文字、数据、图像，记录实际许可和署名；原引擎的上游通知保持完整。

## 模型与界面

`public/knowledge/articles/*.js` 保存逐功能成员内容，`topics.js` 纯投影形成专题文章，`content.js` 校验并冻结；分类仍由 `navigation.js` 与能力登记派生。合并时来源和小节 ID 必须去冲突，并同步映射所有 `sourceIds`；不能删除原始文献或将一个成员的引用误接到另一个成员。每节至少有明确规则和相应资料，每个专题成员至少保留原有完整可核对的输入／输出或结构演算。无来源、无实例、丢失成员、重复／缺少功能、无效关联或危险 URL 直接报错。

2026-10-22：`chapters/*.js` 保存按真实公开能力逐篇撰写的介绍与补充解释；`chapters/index.js` 只做纯内容装配和中性标题整理，不生成菜单、路由或算法。补充内容通过 `preface` 独立保留引用，参与正文搜索与同一阅读器渲染，不计入任何专题成员的机制／实例要求；成员正文仍由原始文章投影且严格校验归属。缺稿或已退役能力残留补写记录均报错，不回退到按名称套用的通用文字。`articles/cipher-examples.js` 保存有完整参数的有限示例及复现配方元数据，在专题投影前绑定真实成员；不加载或替代运算引擎。只含占位说明的例子外壳可并入前一节，但实例、引用与实质规则不得丢失。

公共 `ReferenceList` 通过 `ui/index.js` 使用，外观由组件样式统一拥有，在文章末尾集中展示每项文献一次；正文小节的 sourceIds 仍保留准确的依据关系，不重复生成文献卡片。它显示机构、章节、资料语言，使用安全链接与可访问名称。文献不是软件依赖，不虚构项目来源页脚。目录仍支持领域、主题和正文搜索，手机／桌面保持已有组件与焦点约定。

## 审核与回归

确认引用页面确实有相应内容，分别核验标准事实与本站行为。保留实际阅读证据和未能访问的限制，不把 HTTP 成功或搜索摘要当作全文审核。测试从统一登记检查逐功能／专题唯一覆盖、每个成员正文和完整实例不丢失、来源 ID 重映射、真实双向家族唯一性、工具与科普精确联动、安全链接、简洁名称及配方专用文章已退出独立目录；核验 Base64 分组／填充、盲文点位、SSTV 音调／扫描规则等具体例子。

浏览器验证逐篇正文与旁注确实渲染、真实关联工具可打开、输入保留、阅读焦点、普通／减少动态效果，以及 320／390／800／1440px 和 200% 字号的阅读与链接布局。按 [TESTING_POLICY.md](TESTING_POLICY.md) 选择本轮受影响的内容、专题、组件与布局检查，不因公共组件改变默认执行全站引擎，也不能仅检查文章菜单存在。

## 国内可读的原始实现资料

`vendor/knowledge/UPSTREAM.json` 固定逐文件 SHA-256，独立于实际运行库。`scripts/import-knowledge-sources.py` 是联网维护入口，仅复制已引用的固定 CyberChef 源码和已收录解释器作者文档，不替换原运算文件；原字节、作者头、Apache-2.0／MIT 原文与原始地址全部保留。正文的本地引用保留上游地址及许可证，公共 ReferenceList 显示站内原文、上游链接和实际许可；子目录部署从资源根解析。普通 check／build／verify 只离线核对摘要。

本轮资料与只读独立检查记录见 [复核目录](knowledge-review/README.md)，获取限制与问题发现快照保留；最终处置及完整运行以 CODE_REVIEW.md／VERIFICATION.md 为准。
