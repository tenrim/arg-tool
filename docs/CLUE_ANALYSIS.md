- 一个输入、一份完整输出；候选按格式依据、可读性和原英文频率辅助排序，每次展示 100 项，可继续展开全部候选，可切换查看完整内容、每步依据与实际参数。摘要仅用于列表，后续转换、复制、下载、笔记均使用原完整产物。相同结果合并；所有到达边保留在分析记录中，不捏造正确率。
- 自动串联原 Magic 文本候选、NATO、罗马数字、敲击码、标准无关键词方阵、波多码，以及下文的解谜策略。转换成功不代表语义正确，不宣称穷尽密钥。
- 隐藏字符检查使用原 Invisibles，不自动清理。原字频、IC、熵、重复片段、凯撒候选、维吉尼亚密钥和单表替换入口保留；统计与解码最多 20,000 字符。
- 页面输入最多 64 KiB；默认 3 层，页面直接提供 1–16 层选择，不受全局高级参数开关影响。默认总计 10 分钟、单次 120 秒、8192 次尝试、4096 个节点，不截断单项提案；单输出 4 MiB、累计保留产物 64 MiB。持续模式的 attempts、proposals、totalMs 为 null，允许在所选深度内组合泛用假设；仍保留 16384 个节点、64 MiB 产物、单项超时及去重保护；检查与执行记录合计最多 20 万条，防止诊断元数据挤占内存。达到限制时明确标为不穷尽；引擎失败独立显示，成功分支保留。
- 文本模式把完整、严格有效且无不适合显示的 ASCII 控制符的 UTF-8 原字节转成文本，保留 BOM 和换行；其余中间产物保留为 bytes。非 UTF-8 中间字节可继续原字符集目录；压缩封装继续尝试 GZIP、Zlib、Bzip2，图片／文件展示和解包候选不进入执行白名单。Magic 自身的固定格式探测实现不改写。
- 下载分析记录保留全文、实际配方、关系与失败。非文本节点只导出字节数和前 64 字节预览，格式声明明确该区别，不把预览冒充原始文件。记录不自动保存或上传。
- 停止按钮调用 finish，终止当前实际任务并保留已完成候选；编辑输入、改层数或预算、切换任务、离页调用 cancel 并清空结果租约；迟到回调不能回填。分析深度与预算始终可见，范围说明单独折叠；其他高级参数仍遵循全局设置。

页面所有者为 `public/round1/analysis.js`；`analysis-statistics.js` 展示原统计，`analysis-conditions.js` 复用原参数表单；`clue-analysis/presentation.js` 投影真实执行图。菜单身份、通用组件、笔记数据库和 Worker 客户端继续使用原所有者。

## 本轮扩展及真实边界

- `puzzle-profiles.js` 是固定策略元数据，复用 BYTE_CODECS、CLASSICAL_CIPHERS 和完整键盘映射；`puzzle-worker.js` 调用原实现，未重写算法。覆盖扩展字节编码、整数编码、移位、栅栏、八种古典密码、键盘映射、摩斯／盲文、兽音、佛又曰 V2、两种文字隐写、旗语、T9、英文查词／词格、中文词语模式、拼音／简繁／电码与五种答案提取。移位和栅栏的多个参数算策略，不能冒称独立工具数。
- `catalog-adapters.js` 使用原统计器生成维吉尼亚周期／密钥候选，从完整 Liblouis 目录生成提案，并以原算法尝试全部 312 组仿射参数后按英文卡方排序。会话只继续预算内提案，报告保留提出数量和限额，不宣称所有规则表或参数均已继续执行。
- `chef-puzzle-adapters.js` 补充原 Magic 没有选中的固定文本解码、MIME 编码头，并从原 Decode text 参数目录生成 152 个字符集提案；已是可读 UTF-8 或明确图片／文件签名的中间字节不重复尝试。`conditional-operations.js` 列出需要明确选择算法与原参数的解密入口；这些接口复用原 Worker，不等于所有列出算法都有自动识别或已逐个验收。AES 的真实已知向量已验证；其他条件操作不能引用这一个测试声称全部验证。
- 按层广度优先调度，每层各工具轮流执行一个提案；同一工具的大量参数或后代不会先耗尽其他根工具的预算。已知条件前置步骤的输出成为续接起点，不再重新猜测原始密文。泛用假设的结果仍能继续格式解码，默认同一路径不自动重复泛用假设；持续模式在深度限制内允许组合；记录 `not-expanded`，玩家可“作为输入”继续。词库与电码报告为终止观察，不自动把一整份词库匹配清单当成下一层密文。
- `report.checks` 对当前节点记录 `not-matched`、`needs-input`、`proposed`（已匹配待执行）、`attempted`、`failed`、`not-expanded`。未走到的策略在页面明确标为未检查；解析失败不等于排除该编码。现代密码、密码机不凭空猜造密钥、IV、模式或转子设置。
- `analyze(source, {prefix})` 在同一结果图中先执行用户补齐条件的原操作，再继续分析；前置操作失败不会冒充成功。输入、文字密钥、原操作参数修改都同步撤销旧输出和笔记租约。
- 结果内容按原字节去重，调度路径分别保留实际深度和泛用试解状态。较长的格式路径可以再次开放续接，但不能借用较短猜测路径的深度；同一输入与参数的成功计算复用，不重复启动引擎。用户明确提供的前置步骤按原顺序完整执行，不占用后续泛用猜测层；重复或不改变内容的前置步骤也不被自动去重删除，仍计入转换深度。
- `hunt-extract.js` 是从原页面移出的同一提取实现，原页面与分析共用，避免两份首尾／索引／转置规则分叉。来源统一在 `clue-analysis/sources.js`，使用原随包许可，未更新第三方字节。

这仍不是工具箱整个目录的自动执行器：图形录入、虚拟键盘、字典阅读等本身不是从未知文本推导答案的转换；任意自定义字母表、键盘布局组合、所有密码机设置也没有自动穷举。汉字完整属性、部件、读音、笔画、四角、仓颉、五笔、成语和歇后语查询已接入原完整数据与 API，作为观察结果展示。词库约束替换已调用原求解器，保留其全部返回候选、映射、搜索是否完整和警告，作为终止观察展示，不把多候选报告伪装为一条明文继续递归。

## 已完成范围

- 文字、原始字节、JSON、文件集合四种明确类型；输入和输出均复制快照，保留原始换行、BOM、文件名和字节。文件集合表示调用方已读取的内存字节，不隐式上传或读取磁盘路径。
- 显式处理链和受限的自动候选探索，记录完整结果、实际参数、处理边与判断依据。各类型身份分开；相同结果只存一份，保留不同来源边；相同节点和相同参数不重复自动执行。
- 单会话串行执行，新的运行先终止旧任务；取消、单项/总超时通过 AbortSignal 传播至真实 Worker。CyberChef 已结束的运算（包括输入不匹配）重置会话状态后复用已加载代码；取消、超时、线程或资源故障仍销毁。本站无跨请求输入状态的 worker.js 和 puzzle-worker.js 在单次分析内复用，结束时全部释放；其他引擎保留原生命周期。
- 明确区分完成、部分失败、达到限制、用户取消和失败。无候选只表示本轮已登记规则未找到候选，不代表“没有答案”。
- 原 CyberChef 参数默认值从 schema 提取为纯模型，原页面和底层共用同一实现，原表单导出兼容。

## 所有者和接口

| 文件                                   | 职责                                                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `public/clue-analysis/index.js`        | `createClueAnalysis({limits, textOnly, puzzle, key})`，页面传 `puzzle: true`；原底层调用保留默认兼容范围，导入不启动引擎 |
| `data.js`                              | 类型校验、大小限制、JSON 快照、内容指纹、稳定错误代码                                                                    |
| `registry.js`                          | 内部可信适配器注册与步骤校验；引用原 capabilityId，不维护用户菜单                                                        |
| `session.js`                           | 执行计划、候选图、任务预算、取消与结果失效；无页面/存储访问                                                              |
| `chef-adapter.js`                      | 原 CyberChef Worker、原参数默认值、Magic 候选的完整配方重放                                                              |
| `local-adapters.js`                    | UTF-8、罗马数字、NATO、敲击码／方阵、波多码、隐藏字符与密文统计适配                                                      |
| `worker-job.js`、`worker.js`           | 可终止的原生算法 Worker；只能使用内置操作和固定模块路径                                                                  |
| `public/chef-tools/parameter-model.js` | 原 schema 的 `schemas/defaults/populate` 参数语义；无 UI 依赖                                                            |

```js
import { createClueAnalysis } from './clue-analysis/index.js';

const analysis = createClueAnalysis();
const report = await analysis.runPlan(
  { type: 'text', text: 'QWxmYSBCcmF2byBDaGFybGll' },
  [
    { adapter: 'cyberchef', params: { recipe: [{ op: 'From Base64' }] } },
    { adapter: 'utf8-text' },
    { adapter: 'nato', params: { direction: 'decode' } },
  ],
);
// report.nodes[report.resultId].artifact === { type: 'text', text: 'ABC' }
analysis.cancel(); // 输入/参数变化或离页时同步清除 analysis.result 并中止执行
analysis.dispose(); // 页面实际销毁时释放会话；之后不能重新运行
```

`analyze(artifact, {signal, onProgress})` 使用本轮已登记的 suggest 规则探索；`runPlan(artifact, steps, options)` 执行显式步骤。两者返回独立报告。`textOnly:true` 在公开入口拒绝非文本初始输入，内部编码／压缩步骤仍可保留 bytes。`analysis.result` 读取复制的最新报告；新的输入/任务由调用方显式开始或 cancel，底层不监听 DOM。报告带有 revision，后续异步展示/保存前使用 `analysis.isCurrent(report)` 拒绝旧报告；它只检查时效，成功与否仍看 status。超时报告可显示已完成部分与限制说明，取消的报告不能作为当前结果。进度只含阶段、适配器 ID、数量和状态，不包含线索或结果。回调异常不影响计算。

数据格式：

```js
{ type: 'text', text: '原文\r\n' }
{ type: 'bytes', bytes: new Uint8Array([0, 255]) }
{ type: 'json', value: { rows: [] } }
{ type: 'files', files: [{ name: '结果.bin', mediaType: 'application/octet-stream', bytes }] }
```

JSON 仅接受无循环、普通对象、有限数值；原密文统计中的 Infinity 明确转换为 `{nonFinite:'Infinity'}`，不静默变成 null。未知媒体、结构化记录和二进制结果不自动转成文字。显式 `utf8-text` 使用严格 UTF-8；其自动建议还要求无不适合文字展示的 ASCII 控制符，完整解码仍不证明内容正确。

报告 `nodes` 保存完整类型化产物和最浅到达深度；`edges` 保存原节点、目标节点、实际参数、该路径深度、依据、成功/失败和重复标记。`errors` 包含错误代码和可读说明；`limits` 列出探索被截断的维度；`attempts` 是实际适配器调用次数，包含候选发现。`runPlan` 成功时才提供 `resultId`。不得将 cancelled/failed/limited/partial 当作整次完全成功。

## 已接通的执行边界

| 适配器              | 原能力/引擎                              | 本轮状态                                                                              |
| ------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------- |
| `cyberchef`         | `native:cyberchef` / 固定官方 ChefWorker | 有界本地配方执行；Magic 单层普通模式产生候选，再执行完整原配方，绝不续接 100 字符预览 |
| `utf8-text`         | `native:utf8` / 标准 TextDecoder         | 显式、严格的字节→文字转换，保留 BOM；有界自动建议                                     |
| `nato`              | `native:nato` / 原 completionJob         | 编码/解码；自动识别仅建议解码，使用原 NATO 表筛选                                     |
| `roman`             | `native:roman` / 原 basics.convert       | 编码/解码；自动模式先看字符范围，再由原解析器验证                                     |
| `tapcode`           | `native:tapcode` / 原 basics.convert     | 点数成对识别敲击码；数字成对尝试标准无关键词方阵，保留所用方阵大小                    |
| `baudot`            | `native:baudot` / 原 basics.convert      | 五位分组尝试 ITA1、ITA2、US_TTY，转换参数随路径保存                                   |
| `invisible`         | `native:invisible` / 原 basics.convert   | 自动或显式检查隐藏字符，不自动清理或将检查报告递归当作线索                            |
| `cipher-statistics` | `native:cipher-detect` / 原 analyze      | 显式统计；不把统计 JSON 当作下一层线索自动分析                                        |

CyberChef 明确支持的操作列表由 `LOCAL_CHEF_OPERATIONS` 导出，当前包含经检查的本地解码/解析及 To Base64、To Hex、Analyse hash。默认参数来自随包 catalogue 和原参数模型；显式 args 沿用原引擎。每条配方 1–8 步，保留解析后的完整参数供重放。Magic 固定单层、普通模式、无扩展语种和 crib；外层负责跨引擎深度。原 Magic 内部试探不是外层 attempts 的逐步计数，但受整个真实 Worker 的单项时间限制。

通用底层遇到未接通的渲染 HTML、图片/PDF 展示、解包等候选会返回 UNSUPPORTED。页面文本模式明确筛除这些范围外的候选，不宣称全目录覆盖；编码结果仍保留非文本类型，不作有损显示。既有 CyberChef 页面与完整引擎不受此名单限制。后续新增实际支持需检查输入输出类型、取消、参数和来源后加入名单，不能仅因 catalogue 新出现某操作就放开执行。

本轮不接入二维码图像、音频、科学资料、在线查询或服务器文件分析；文件集合仅保留底层数据契约，没有自动文件处理分支。不通过模拟点击或读取结果 DOM 执行。`external` / `recommendation` 类型的登记只能用于说明可用方向，执行会返回 INTERACTION_REQUIRED；没有后台上传或外部查询。

## 预算与错误

默认输入 1 MiB、单个输出 4 MiB、累计保留产物 16 MiB、48 个不同结果、64 次调用、每次候选发现最多处理 16 项、路径深度 3、单项 8 秒、整次 30 秒。这是兼容底层调用的默认值；页面使用上文的宽松预算。预算可在 createClueAnalysis 时配置；attempts、proposals、totalMs 允许 null 表示不设该项限制，其他维度仍有硬上限；每会话并发固定为 1。深度计算中一条 CyberChef 配方按实际操作数计入，类型转换也计一步。数量/内存/时间达到上限保留已完成的部分并明确报告，不宣称穷尽所有候选。

保留产物预算不等同于整个浏览器的进程内存上限；引擎加载和瞬时工作内存仍由原引擎承担。解析/哈希身份不作为正确性评分。原 Magic 候选顺序保持，跨类型结果不合并成虚构的正确率；分析证据分为格式提示、原引擎已执行、统计候选等。

稳定错误代码：`INPUT_INVALID`、`UNSUPPORTED`、`INTERACTION_REQUIRED`、`LIMIT_EXCEEDED`、`TIMEOUT`、`CANCELLED`、`ENGINE_UNAVAILABLE`、`EXECUTION_FAILED`。自动试探中的已知解析校验错误记录为 rejected，固定引擎不支持的选项记录为 unavailable，均保留原错误但不冒充引擎故障。未知异常、引擎加载失败、超时仍进入 errors；显式步骤和用户前置步骤失败仍失败；全局取消不允许迟到结果发布。适配器是项目内部可信模块，不是供用户上传脚本的插件接口；新适配器必须实现信号取消，单纯 Promise.race 不能代替终止计算。
