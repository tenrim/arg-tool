# UI 开发强制规则

验证范围遵循 [TESTING_POLICY.md](TESTING_POLICY.md)：日常只测受影响契约；本文列举的是保留的覆盖能力，不是每次改动的执行清单。完整检查使用 `npm run verify:all`。

适用于所有新工具、现有页面和共享组件改动。根目录 [AGENTS.md](../AGENTS.md) 要求先读此文；接口见 [UI_COMPONENTS.md](UI_COMPONENTS.md)，目录与工作区契约见 [CAPABILITY_ARCHITECTURE.md](CAPABILITY_ARCHITECTURE.md)。这些约定同时由源码检查、构建、浏览器回归和 CI 执行。用户明确改变产品要求时更新规则及检查，不能为通过测试而加入页面豁免。

## 组件与职责

1. 页面只从 `public/ui/index.js` 导入公共工厂、组合接口和控制器。初始页面也从该入口挂载。新增通用行为先实现为共享组件，页面只组合组件、连接数据和专用图形。
2. 常规 HTML 由真实组件工厂或 `render` / `insert` 创建。禁止页面调用 `createElement`、写 `innerHTML` / `outerHTML`、`insertAdjacentHTML`、`createContextualFragment` 或 `new Option`。补 `data-ui` 不构成组件实例。
3. `ui-theme.css` 维护配色和字体，`ui/components.css` 是最后载入的公共外观、状态、尺寸和动效层。工具 CSS 只定义布局与图形，不自行覆盖组件边框、字号、颜色、焦点或复选框排列。公共默认定位使用低优先级，不能覆盖已有 sticky / fixed。
4. Canvas、SVG 几何和计算引擎属于工具渲染层；不可信 SVG 必须走独立白名单，不得借用图形命名空间绕过 HTML 工厂。保持固定上游运行字节、原始来源及许可证。
5. 壳层负责导航、页头、收藏、搜索和帮助。新页面必须登记统一目录，提供中国用户能读懂的名称、图标和使用说明；引入第三方代码、数据或素材的工具，页末必须列实际项目及精确许可证；纯本站实现与网站页面不添加来源栏。浏览器接口与 MDN 不是项目来源，不保留空标题或原生接口占位；来源归属由 project-sources 在依赖组合完成后统一处理。不得增加额外窗口、iframe 或第二套导航。
6. 网站级首页、关于、设置与工具目录分开登记，默认进入首页，工具深链接优先。首页与弹窗目录使用同一 ToolCard；设置由共享组件与动效层应用，不给单页设置视觉补丁。偏好只持久化合法选项和主动收藏，最近使用只在会话内记录；选择上次工具作为启动页时才保存一个工具 ID。导入先验证完整数据，失败不得部分覆盖；备份不包含工具输入、文件、结果或草稿。

## 能力发现与工作区

- 正式五类：编解码与加解密（`codec`）、资料查询（`reference`）、图片音视频与文件处理（`media`）、其他工具（`other）、科普（`knowledge`）。用户明确新增科普后，此约定替代此前四类约定。公共分类／能力组定义与旧兼容路由在 `navigation.js`，真实任务归属在 `capabilities/registry.js`；首页、侧栏、总览、目录和搜索从统一登记派生，不各自维护标题、数量或别名。
- 分类总览直接显示全部能力组，每组展示能代表不同用途的少量功能和真实数量；“全部 N 项”就地展开完整列表，其他组保持可见。完整目录只保留一层搜索、分类筛选与组索引，不把未知功能藏在多级下拉菜单里。
- 全局搜索默认覆盖五类，中文名称、英文原名、专业词及玩家描述共享同一匹配入口。代表功能、搜索结果和完整列表到达同一个真实任务，不另做示例版算法。
- 保留桌面原侧栏与手机同节点抽屉。任务页保留当前路径、必要选择、参数／输入／结果、使用说明及返回组／全部功能，不再重复展示整棵分类树；桌面充分利用宽度，手机自然堆叠。
- 侧栏大分类名称到总览，独立展开按钮只控制列表；组内具体工具／科普直接到工作区／正文，单工具组不再增加中间层。侧栏搜索直接输出真实任务链接，保留方向与排序；分组只在侧栏展开，不导航到组总览。所有列表、数量、链接及当前能力来自登记，不另建默认工具映射。
- 导航层只连接或移动原组件，保持原引擎、参数值、文件和监听器。旧深链接、工具收藏、最近使用与设置格式继续兼容；不能将新能力 ID 直接替代原受校验工具 ID，不能把输入或结果放进偏好。
- 同类型已支持的加密／解密、编码／解码必须登记为一个可发现的功能族，方向按钮直接显示当前实际操作。`registry.js` 统一拥有 `CHEF_OPERATION_PAIRS`、原生方向、操作归属 `byOperation` 与旧入口 `aliases`；原工具选择、CyberChef 索引和处理链选板通过 `chef-tools/families.js` 从该登记派生，不再维护配对或逆向清单。原配方仍保存全部原始操作 ID，数量区分功能族与底层操作，不能通过删除解码操作减少重复。
- 旧单向能力 ID 用 `resolveCapability` 解析为功能族及原操作／原生方向；明确搜索某一方向时仍到达该方向。切方向同步取消旧任务、作废旧结果，保留原输入与方向独有的参数草稿，只共享兼容具名参数。“反向处理结果”或“继续处理结果”显式采纳真实结果字节；方向按钮不能自动替换输入。结果续接与反向共用同一采纳所有者，保存已执行操作及参数快照，首次进入其明确逆向时以来源输出／输入格式初始化目标输入／输出，仅接受两边声明的兼容格式。外部采纳清除旧归属，不按当前表单猜格式，也不重设用户后续修改。不给哈希、有损清理或签名推测逆向，不承诺所有双向操作无损往返。
- 资料页使用真实索引与当前详情对象，联动使用该对象；媒体保留原始文件与当前结果的区别；棋谱、网格和模拟共用组件外壳，各自的规则、状态、撤销与单步模型独立保留。不能为统一布局将这些模型强制改为同一种表单。
- 科普独立于资料查询，且每项可见功能单独一篇（双向功能族一篇），禁止工具组概论充当具体功能科普。`knowledge/articles/` 分片在 `content.js` 校验与冻结；主题从现有工具组派生，不复制另一份分类。文章以 `learn:<articleId>` 登记，`capabilityIds` 建立精确且唯一的工具关联。每节必须以 `sourceIds` 引用支持其具体机制的权威原始资料，正文有步骤、输入／输出实例与边界。新增可见功能必须同时补充独立文章，数量从内容和登记派生。详见 [科普内容规则](KNOWLEDGE_CONTENT_RULES.md)。

## 排布与交互

- 使用 `SearchField` 组成单个焦点表面；`FormGrid` 按容器宽度决定列数，`Field` 表达全宽及复合参数；相关布尔值用 `CheckGroup`；输入／结果用 `SplitView`。保留参数顺序、原始值和整行 label 激活。
- PC 有效利用宽度，窄屏按内容自然堆叠，避免以手机单列设计覆盖桌面。控件不裁切；长文本可换行，表格及长结果内部滚动。手机点击目标至少 44px；不能仅靠 hover 提供操作。
- 使用有界自动高度 `Textarea`，程序写入用 `setTextareaValue`；空结果使用 `EmptyState` / `Result`，不保留大块装饰留白。不能为了排版截断原始字节或输出。
- 表单控件必须有可访问名称；图标按钮必须有 label；复合字段的每个控件分别命名。保留明显焦点、键盘顺序和语义，禁用标签在点击、键盘、程序选择及初始选择中均不可激活。
- 标签、弹窗、展开说明分别使用 `tabsController`、`dialogController`、`disclosureController`。页面不能另写焦点恢复、ARIA 或开关时序。组件移动须保留原节点、文件、输入和监听器。
- 常驻工作区只呈现控件、真实状态与结果。操作步骤、功能介绍和重复的本地运行说明集中在页头“使用说明”，来源与授权集中在页末。已有说明覆盖的静态段落直接删去；动态说明节点以 `data-tool-help` 交给共享帮助，晚载内容使用 `appendToolHelpContent`，保留 ID、ARIA 引用和动态更新。不能用 CSS 批量隐藏 `.help`／`.ref-note`，这些类也承载有效读数与错误。
- 科普文章是用户明确要求的阅读内容，具体机制、例子与紧邻的权威文献直接呈现；阅读操作说明仍在共享使用说明。复用 SearchField、Card、SplitView、Result 和 ReferenceList，桌面目录／正文并排，手机切换并恢复焦点，重入同篇不重建正文。优先国内官方资料及标准镜像；原文语言如实标示。来源引用区别于软件依赖，第三方文本、数据、素材若实际复制仍按其许可证保留署名。

## 动效与生命周期

- UI 动画由 `ui/motion.js` 和 `ui/components.css` 统一拥有。页面只调用公共 `animatePresence` / `animateCollection`；不能直接调用 WAAPI `animate`、写 animation / transition 内联样式，或增加页面关键帧与过渡。算法必要的 Canvas / WebGL 帧循环仍属于专用渲染，切页即停。
- 统一令牌：按压 100ms、焦点／反馈 140ms、进入 180ms、展开 200ms、弹窗／侧栏 220ms，曲线 `cubic-bezier(.2,.8,.2,1)`，JS 读取同一组 CSS 令牌，支持 ms／s 并保留 0ms。触控位移更短，公共时长只能在组件样式中调整。忙碌转圈只用于真实执行状态。
- `ToolPanel` 根节点只淡入，不能变换包含 sticky / fixed 的页面根。动画必须可中断，从当前状态继续；集合使用稳定记录 ID，不用数组位置当身份。
- 连续输入、过滤、拖动、进度和图形每帧更新不反复播放进入。所有动效入口共用连续输入抑制；持续计算的只读文本使用 `setTextareaValue(node, value, {feedback:false})`，单次操作保留默认反馈。抑制动画不能阻止同步更新结果或公共自适应高度。
- hidden、inert、ARIA、焦点、取消和输入作废立即生效；动画不延迟逻辑、不复制用户内容、不推断 disabled 就是 busy。过期回调必须带修订号或任务 ID，不能覆盖新状态。
- 原生弹窗关闭及恢复焦点同步完成；退出只延迟视觉清理。保持退出期间纵向布局与可见视口尺寸；重开、销毁或完成时释放快照。抽屉保留原侧栏至退出完成，不能复制节点。
- 同时支持 CSS 与 JS 的实时 `prefers-reduced-motion`。隐藏、卸载、进入后台和偏好变化取消动画；没有能力支持动画时仍立即完成操作。不能用仅关闭动画的测试代替正常动效测试。
- 控制器和组件注册 `onDisconnect`，清理事件、ResizeObserver、RAF、Worker 或持有的动画。相关说明的按钮或面板任一端卸载都要清理；销毁可重复调用且不能再改变状态。同一批次内搬动节点不视为卸载。

## 数据与异步状态

输入、文件名和结果走 `text` / `value`，或在开发者模板中明确转义；模板不是通用 HTML 净化器。结果模型与展示分离，下载和续接使用真实字节。异步操作必须有输入变更失效、取消、限额、超时、失败恢复与过期结果防护。真正成功才标成功；清空、停止和失败不保留旧结果。默认本地处理，不暗中联网或上传文件。

Worker 的引擎、模块、字体、数据和 WASM 地址由页面模块的同源绝对基址决定，不能依赖临时 `blob:` 线程地址。共享加载适配须保留上游字节与显式联网操作语义；加载失败要明确传回任务并终止，不能只等待全局 error 事件或运行超时。引擎回归必须包含普通、Blob、子目录启动和失败后重试，并断言实际输出。

## 根因修复流程

1. 先复现失败操作，记录输入、组件状态、视口和正常／减少动态设置。检查问题来自组件契约、控制器状态、层叠优先级、资源路径、结果模型还是引擎适配。
2. 用行为断言保留失败场景，再修正拥有该职责的共享层。不能只加页面 CSS、固定延迟、隐藏错误或降低原有边界断言。
3. 检查所有消费者：动态参数、按需页面、手机抽屉与键盘、PC 多栏、快速交互和卸载。新增回归同时验证即时逻辑与动画结束状态。
4. 本轮受影响检查通过后更新验证记录和修复说明；交付发布产物时验证对应构建。文档说明实际检查范围，不能将浏览器模拟冒称实体设备验收或将旧通过结果冒称本轮结果。

## 自动检查与交付

```bash
npm run test:plan -- --files public/ui/controls.js
npm run verify -- --files public/ui/controls.js --report /tmp/arg-verification.json
# 明确需要完整验收时才运行；不是上述命令的必做后续
npm run verify:all -- --report /tmp/arg-full.json
```

`audit:ui` 检查公共入口、HTML 工厂、动效／令牌／样式所有权、最后的组件样式层、唯一目录和必备帮助；`check` 和 `build` 也执行它。静态检查是明确语法边界的检查，不是完整 JS/CSS 语义解析或安全证明。安全展示、真实实例、焦点、逻辑状态、尺寸和动画契约由实际 Chromium 用例保障。

新增回归登记到测试映射和完整 `verify:all`，不得只放一个手工可跑的孤立脚本。组件行为、布局、动效专项与全部工具测试必须保留，按实际影响选择执行；覆盖 320／390／800／1440px、手机横屏、放大字号、可见视口键盘与桌面宽屏。能力登记需验证来源覆盖和唯一归属，浏览需验证全部组／就地展开／五类搜索，迁移需验证旧链接和偏好、真实任务输出、输入保留及跨任务结果作废。功能族回归保留全部原始操作、两个真实方向及方向独有参数；科普验证逐功能唯一覆盖、正文与可核算例子、逐节权威引用、安全资料链接、精确关联能力、阅读焦点及取消后旧回调不回填。计算改动必须断言实际引擎输出。当前 CI 是 GitHub Actions，Gitee 尚无云端验证流水线，需本地执行受影响检查。GitHub CI 按分支差异选择，手动 full 可运行全套；启用 CI 的仓库应要求本轮选定检查通过才允许合并；配置要求通过检查和禁止直接推送的仓库分支保护需由仓库管理员开启，本地规则不能代替服务端权限配置。

- 有界记录目录使用公共 Result 的 collection 与 Button 的 stacked 布局；标题／摘要／标签必须各有真实内容高度，不可只验证按钮本体 44px。校验邻行及子节点边界、200% 字号和滚动。公共侧栏跨断点即时同步正文让位，主动桌面收展才应用对应过渡；原节点、偏好和键盘操作继续保留。

输入／输出格式在双向算法中分别描述明文侧与密文侧，是方向独有参数；同名、同类型不代表同语义。普通切换保留目标方向的草稿或真实默认值，Key／IV／Mode 等相同角色参数才共享。显式结果采纳的格式初始化使用已执行快照，不能用未采纳的预览或当前参数推断。回归必须覆盖首次加密／解密默认格式、目标手改格式往返保留，以及 Unicode 结果续接的独立密文与原字节对照。
