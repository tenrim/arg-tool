# 视频工作台

此功能从 V2.2 起提供。版本变更见 [V2.2 更新日志](releases/V2.2-更新日志.md)。

2026-11-14，本地修订，未部署或推送。

## 本轮修正

此前所有 FFmpeg 表单共用 5 秒默认值及 30 秒上限；音轨命令始终附加 `-t`，造成整段音频无法通过音轨提取入口导出。隐藏的时长、帧率也参与所有操作的校验。连续帧强制截断到 30 张并缩小到 960 像素，倒放缩小到 640 像素并移除声音。

现在默认完整媒体，指定片段才使用起点和长度。音轨可选择第一条、指定序号或全部分别输出，支持 WAV、MP3、M4A、FLAC 和保留原编码的 MKA；不强制改变采样率或声道数。连续帧默认保持原尺寸，帧率、缩放宽度和数量上限明确可见，预计超限时拒绝执行而不是截断输出。倒放默认同时反转声音，可关闭音轨。

新增正常表单入口：视频裁剪、移除音轨、缩放、旋转／翻转、变速、文字字幕提取、媒体信息与轨道；固定核心完整帮助也可从功能选择进入。六种原格式转换、原生 JSON 命令、多文件原生命令输入以及原 GIF/APNG 工作台保留。只处理单个文件的操作会拒绝多个输入；拼接、换音轨和声道重组使用明确的多文件顺序，不默默只取第一个。

FFprobe 提供原始轨道、编码、时长、采样率与画面尺寸；信息页导出完整 JSON。新操作共用原 FFmpeg 核心，未更新上游字节。低帧率视频变速通过输出帧率与时间戳共同调整，避免只有声音缩短。

## 运行边界

- 本机浏览器计算，不上传。输入合计 256 MiB；完整输出 256 MiB／1000 个文件；单任务 10 分钟，日志 16 MiB。它们是浏览器保护条件，不是 FFmpeg 算法的固有限制，也不保证所有设备在限额以内都能承受解码内存。
- 连续帧默认上限 300，可设至 1000；实际是按采样帧率提取，不冒称源文件所有原始帧。超出输出上限不会发布部分结果。
- reverse 会缓存解码帧，长视频或高分辨率建议选择片段。视频常用表单输出 H.264/AAC，去音轨采用原视频编码 MKV；不是所有转换都无损。
- 文字字幕转换为 SRT，复杂样式不保留；图像字幕和烧录在画面上的字幕不作为文字轨提取。
- 参数、素材、任务切换和离页作废旧结果及笔记租约，停止直接终止 Worker 与资源下载。失败提供可下载的完整日志。预览可截日志末尾，但下载不截断。
- 缓存的仅是固定 WASM 字节，每次任务使用独立 Worker 和内存文件系统，完成／失败后释放；不保存媒体输入或跨任务共享结果。
- 自定义命令保留原本地文件协议边界，不强迫先将首个文件识别为媒体（允许拼接清单等原生用法）。固定核心的完整能力不等于全部有专用图形表单。

`public/video/commands.js` 负责表单参数验证与原生命令编排；`runtime.js` 拥有 FFmpeg Worker、取消、完整输出与日志；`index.js` 拥有唯一文件输入、表单、结果展示和原笔记租约。`hunt-media.js` 仅装配视频工作台，图片条码、立体图和 SSTV 的原所有者未迁移。原动画模块继续通过相同文件输入挂载。

功能、搜索、路由、专题成员、来源及逐成员科普同步登记，新增功能不用另一套菜单。没有修改公共配色、扫描线或固定第三方文件。

## 实际验证

`scripts/browser-video.mjs --case=runtime` 使用系统 FFmpeg 生成 45 秒、64×48、双音轨、含文字字幕的合成视频。处理运行在 Chrome 内的本站固定 WASM 核心，桌面 FFprobe 只独立核对导出的真实文件：

- 两条完整 WAV 均超过 44.9 秒并保持 16 kHz；3 秒起点提取 35 秒；MP3、M4A、FLAC、原编码 MKA。
- 连续帧超过 30 张且保持 64×48；超出用户帧数上限、轨道不存在、起点超时长均明确拒绝。
- 单帧、裁剪、去音轨、缩放、旋转、变速、双音轨倒放、GIF、SRT 和完整元数据；六种原格式转换。

`--case=edges,ui` 验证损坏文件、无音轨、无声视频倒放、原生命令、隐藏参数不参与无关校验、完整核心帮助；实际页面完整音频、参数改变作废、各新功能路由、动画切换、停止与 390px 无横向溢出。已查看手机截图。新增模块依赖与 UI 所有权检查通过。

未整套重跑图片、SSTV 或其他工具。旧媒体 smoke 和笔记用例只同步“先选指定片段再填时长”的交互步骤，没有将这些广范围脚本宣称为本轮全量通过。测试产生的合成媒体保存在忽略目录 `outputs/ffmpeg-review/`。


## 第二轮：七项媒体编辑功能

2026-11-14，用户指定的七项功能已接入本地工作台，未部署、提交或推送。

| 功能 | 实际行为与边界 |
| --- | --- |
| 拼接 | 音频／视频两种模式；2–20 个文件，可上下调整顺序。视频按首项尺寸等比留边、30 fps；每项取指定序号音轨，缺音轨的视频补静音。音频统一 48 kHz 双声道，分别输出 MP4 或 24 位 PCM WAV。 |
| 换音轨 | 第一项视频、第二项替换声音；选定音轨。保持视频长度并补静音、循环短声音、截到较短长度三种策略。视频流复制，声音 PCM，输出 MKV；明确仅保留所选画面与音轨。 |
| 画面裁切 | 按正常播放方向的像素坐标填写左、上、宽、高，处理直角旋转标记；0 宽高延伸到边缘。越界和奇数宽高拒绝执行，不暗改坐标。H.264／AAC 输出并保留全部音轨。 |
| 异常片段检测 | 黑屏、画面冻结、静音，可选单项或全部，设置阈值和最短时长。可读区间、定位原文件预览、完整 JSON／CSV／原日志。跳过不存在的流类型；结果表示候选而非损坏或解谜结论。 |
| 多时间段导出 | 每行起点、终点，按填写顺序分别输出，可重叠，最多 100 段。视频 MP4 保留全部音轨，音频 WAV 取所选音轨。先验证所有区间，失败不发布部分结果。 |
| 音画同步 | 有符号毫秒偏移，正数延迟、负数提前；保留视频时长，缺处补静音，超出裁掉。MKV 视频流复制，声音 PCM，选择要调整的音轨。 |
| 声道拆分与重组 | 按索引拆出每个声道（最多 64）为 24 位 PCM WAV，保留采样率。1–8 声道重组用“文件:声道”映射，可跨文件、复制、交换顺序；统一 48 kHz、最长来源时长，短来源补静音。布局由输出声道数明确确定，界面及科普说明。 |

`editing.js` 负责这七项纯命令规划与检测日志结构化，`editing-ui.js` 负责共享组件参数和条件显示。主控制器仍是唯一文件与结果所有者；文件列表仅重排原选择的 File，改序即取消任务并作废结果。所有文件先探测，普通多输入使用内部编号，因此支持中文及同名输入；原生自定义命令保持原文件命名约定。单任务最多 20 个输入，其余浏览器限额沿用上文。

流时长优先读取对应流，兼容 Matroska 的 DURATION 标签，不把较长音轨导致的容器时长误当作画面时长。检测保留不同流在文件中的时间偏移；没有冻结结束日志的尾段以探测到的流末尾收束。FFprobe 的 error 日志级别会影响同一核心的 FFmpeg 执行，运行器每次显式恢复 info，确保原检测事件与诊断不丢失。

本轮 XERJ SearchProject `planMedia mediaJob` 未命中新模块，随后直接读取已知所有者 `public/video/`。SearchReference `omnitools` 的 `concat crop audio` 命中同一固定提交 `60bc64f5a6974f3c802c5ec06cb3cf7f824485e1`：`src/pages/tools/audio/merge-audio/service.ts:5–64` 和 `src/pages/tools/video/crop-video/service.ts:29–65`。参考任务隔离、输入规范化与 crop 原滤镜调用；没有复制上游界面或算法。新功能仍调用固定原引擎，依据 [FFmpeg 原滤镜文档](https://ffmpeg.org/ffmpeg-filters.html) 中 concat、crop、apad、atrim、adelay、blackdetect、freezedetect、silencedetect、pan、amerge 与 aformat；新增七项均有独立工具入口、搜索与路由、来源及逐项科普。

### 第二轮实际验证

`scripts/browser-video-editing.mjs` 在 Chrome 中运行随包 WASM，使用独立合成素材；桌面 FFmpeg 只生成输入并读取输出用于核对，不替代产品执行：

- 拼接顺序通过末段红色像素验证，核对不同尺寸、无声视频补静音与音频拼接总时长。
