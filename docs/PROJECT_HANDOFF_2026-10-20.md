## 三 用户反复确认的产品要求

### 完整接入和修复方式

- 优先复用有真实能力的开源项目；先核查许可、固定版本、实际内核、完整数据与接口，再设计本站的接入方式。
- “完整”必须说明对象和范围。完整固定版本、完整选定标准是可验证的承诺，不等于复制一个网站全部商业数据库、账户体系和桌面系统能力。
- 不接受仅改名称、拼接外壳、做几个示例算法、保留装饰参数，或把未实现功能写进公告。
- 结果可以分页、预览和折叠，但计算、导出、笔记保存不能暗中丢数据。必要的资源上限明确报错或说明，不能把未完成枚举称为完整结果。
- 修复先复现和定位真正所有者，再修组件、数据模型、引擎适配或资源路径，并覆盖相同问题的其他使用处。禁止只用 CSS 遮盖错误、固定等待或针对截图的补丁。

### 分类和工作区

- 五大分类为编解码与加解密、资料查询、图片音视频与文件处理、其他工具、科普。
- 同一明确用途的碎片功能合成专题：信息提取、PGP、Base 家族、字符编码与码点、数字与字节编解码、文字转义、二维码与条形码、代码运行等。
- 一个专题计一个可发现入口，专题内部选择真实操作；不能把不同用途只因同组就塞进一个页面。
- 同一页面里保持真实引擎的接口和结果模型。二维码的 ZXing、QRazyBox／jsQR、CyberChef 不能因合并 UI 就被强行改成同一种输入和状态。
- `native:radix` 对整个整数换进制；Binary／Decimal／Hex 字节表示不是同一个算法，不能切换时悄悄改变输入单位。
- 首页只有已收藏、最近使用、工具导航，不增加宣传区。全部功能、侧栏、分类、搜索共用登记模型。
- 页面保留标题、收藏、相关科普、使用说明、返回分组、全部功能。不要恢复面包屑、同组功能横排或重复方向按钮。

### 数学功能的最新边界

- 早期删除大量方程、基础算术、位逻辑等独立菜单的决定仍成立；这些 CyberChef 操作在完整配方中保留。
- 后续用户明确选择 **M01 Qalculate 综合计算器**，要求完整内核、全部函数和单位。它是最新授权的综合工作区，不应借旧规则把其数学函数删掉。
- 通用单位换算统一到 Qalculate，一个单位不能被拆成一个工具入口。
- Alpertron 当前只开放整数表达式、素性、因数分解、除数验证和批处理；旧的九项高级引擎不恢复为菜单或接口。
- 当前 CyberChef 配方专用策略在原 78 项基础上增加了 5 个旧单位换算操作，变为 83 项；另有流程控制等既有边界。不要把这些数量混成可见工具总数。

### 笔记本和结果联动

- 笔记、思维导图和线索白板属于同一笔记本，不能登记成“其他工具”的三个独立功能。
- 规范入口为 `#notebook`、`#notebook/mindmap`、`#notebook/whiteboard`，旧独立入口只归一到笔记本。
- 桌面点击笔记本使用当前页面右侧可调整宽度的笔记面板，并提供进入独立笔记本页面的按钮；小屏保留合适的完整视图。
- 工具结果应能加入笔记本及笔记图稿。用户后来明确要求“用其他工具处理”保持删除，也不恢复“送到处理链”快捷按钮。
- Excalidraw 不强迫手绘外观，不用整体颜色反转来硬凑深色模式；Mind Elixir 应使用项目真实编辑特性。
- 笔记事务拥有选中笔记和存储，图稿控制器拥有场景。保留附件、图稿 ID、来源字节、预览和备份，不建立第二套数据库，也不让两个队列互相等待。
- 笔记数据库已升级到 IndexedDB 版本 2。浏览器源变化或回退旧代码前先导出兼容备份；不能清库解决版本问题。

### 中文资料和外站说明

- 中文适配优先原项目和权威资料中的正式中文字段或对照数据，不靠维护者手工编一份小库。
- 没有对应中文时保留原文并准确说明，不能把社区转载冒充官方翻译。
- 在线结果优先展示对玩家有用的基本信息，不能只有词条标题，也不应把查询调试信息和大量无关技术字段堆在正文。原始完整结果仍保留在下载、复制和笔记中。
- 诗、词、赋和散文按其实际结构展示，不能机械地在每个逗号后换行。
- 外站指南放在资料查询的子菜单；按方向列出多个网站，每个网站仍有详细介绍。
- 用户要求去掉模板化的“怎么查、和本站区别、使用边界、适合线索”等段落；保留真正有内容的详细介绍。宽泛的中文维基百科、萌娘百科、百度识图等不因此收录。
- 图像编辑与分析的外站方向包括 AperiSolve。它是外链介绍，不要冒称完整服务端扫描已经在本站运行。

### 启动及部署

需要 Node.js 24 或更新版本。常规前端运行和构建不需要全站 `npm install`；维护导入或特定后端依赖按各自说明处理。

本地指定本项目端口：

```powershell
$env:PORT='16321'
npm start
```

不指定 `PORT` 时服务默认 3000。先检查端口占用和原进程，避免为绕过问题不断另开端口。根启动命令包含必要的 vendor 准备；日常运行不重新联网编译 Qalculate。

服务器采用 1Panel Node.js 运行环境，项目目录为仓库根目录，命令 `npm start`，OpenResty 将网页和 API 转发至同一运行环境。目标是正常 Git 同步后重启即可更新；保留服务器私密配置，不能用覆盖 `.env` 或清理未知文件来“修复”。

部署细节读 [部署说明](DEPLOYMENT.md) 和 [邮件服务交接](HANDOFF_FEEDBACK.md)。启动日志 `FEEDBACK_READY` 只证明本地服务就绪；SMTP 连接登录检查不代表真实邮件投递。历史上只曾授权特定的一封测试邮件，不能无限沿用为后续发信授权。

本文件不保存密码、SMTP 凭据或 SSH 私钥。历史服务器身份和密钥位置可从维护者已有配置核对；部署前重新核实主机、指纹、运行目录和远端，不能仅凭旧聊天猜测。切换新对话不应要求用户再次把密码贴进普通文档。

用户的原始要求是接入项目完整内核、400 多函数和单位，优先获得完整计算器能力，并统一原有单位换算。当前不是用自写小算法模仿 Qalculate。

- 表达式、多行工作表、单位换算，以及完整分类函数／单位／变量／前缀目录。

- 当前结果加入笔记／白板／脑图，保存文本、绘图、生成文件及包含完整数据的 JSON；二进制按明确编码保留。

### 实现、资源和已知范围

- `public/qalculate/index.js`：本站公共组件组成的真实工作区。
- `client.js`／`worker.js`：计算、设置、虚拟文件和任务生命周期；取消或超时终止 Worker，不能让旧 Promise 杀掉刚启动的新 Worker。
- `model.js`：纯目录、翻译、报告、会话校验及二进制序列化；`files.js`：虚拟文件枚举和完整性限制；`plot-worker.js`：真实 Gnuplot。
- `public/vendor/qalculate/`：固定 WASM、JS、中文、完整来源摘要、各依赖许可和 `source.zip`。
- `upstream/qalculate/`：独立桥接及构建脚本，编译全部 41 个官方 `.cc` 和完整 `definitions.cc`；不修改官方核心源码，也不采用旧包装器的小版本内核代替当前内核。
- `source.zip` 含对应核心、依赖、桥接、构建资料及匹配 WASM 静态库；`.gitignore` 已为它添加例外，后续提交必须确实包含该文件。
- `sourceArchive` 是来源模型的独立源码下载字段，不可把二进制 ZIP 放入供正文读取的 `notices` 数组。
- 本站接入完整计算内核与原生网页工作区，**没有嵌入 Qt／GTK 桌面窗口**。浏览器不能执行宿主系统命令或任意读宿主文件；不能把这些桌面能力写成已经实现。
- 货币使用随包汇率快照，不是实时行情，也不会进页自动联网更新。
- 单次计算有 60 秒时限；虚拟文件系统有明确容量／文件数限制。限额失败不返回删减后的“完整结果”。日常运行无需新增后端或 Docker。
