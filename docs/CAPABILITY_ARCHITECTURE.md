# 能力目录与工作区架构

## 笔记本与工具的边界

2026-10-18：桌面从导航打开笔记本时，使用右侧非模态、可调宽度的笔记侧栏，不改变当前工具路由或发送工具离页事件。`app.js` 编排打开方式，`ui/dock.js` 只负责原节点搬移、宽度、指针／键盘、焦点和窄屏回退；`notebook/page.js` 保持唯一编辑器、存储与保存队列。工具切换时侧栏可继续记录；关闭不销毁编辑器，完整页面和侧栏之间移动同一节点。笔记列表在侧栏内折叠，完整页面恢复原双栏布局。明确的 `#notebook` 深链接、窄屏以及脑图／白板编辑仍进入完整笔记本页面；不建立第二套数据库或复制编辑器。来源显示由 `project-sources.js` 的笔记视图接口恢复，不干扰当前工具来源。专项 `browser-notebook-dock` 覆盖工具结果与节点保留、保存、拖动和键盘调整、图稿切换、手机及两种动效偏好。

笔记、思维导图和线索白板属于网站级笔记本，不是五类工具中的独立能力。`navigation.js` 的 notebookViews 定义三个笔记本视图；同一个页面提供标题、笔记列表、当前笔记图稿及帮助。`#notebook/mindmap`、`#notebook/whiteboard` 由 app.js 解析为笔记本内部视图，不走任务能力渲染器，不进入工具计数或工具科普。全局搜索可发现笔记本入口；原有附件、来源及备份数据不变。图稿本身的生命周期和引擎仍由 graphics 所有，存储与笔记选中状态由 notebook 所有。

## 2026-10-16：专题工作区与统一任务入口

用户明确取消聚合工具页；首页、分类总览、全部工具目录和科普目录保留浏览职责。2026-10-16 起，同一明确用途／对象的真实任务可合并为一个专题工作区，例如信息提取、PGP、JSON、英文查词、视频处理、代码运行和纸笔解题。专题表单允许选择其登记的实际操作／变体，这替代旧版禁止任务内操作选择的约定；不能恢复全站分类／搜索选择器、整组泛总览、处理链重复目录或第二套渲染器。

专题定义在 `capabilities/topics.js`，`topic-model.js` 只将原始能力投影为专题记录，不加载工具实现。每个专题拥有完整 `sourceOperationIds`，Chef 成员在 `actions`，原生成员在 `variants`；混合专题同时声明两种成员，并在 `variants` 保留每个实际实现的 `open`、原始操作及控制器目标。原始操作仍有唯一 `byOperation` 归属。配方专用成员先由 `operation-policy.js` 过滤，过滤后不足两个实际所有者时不强行生成专题。侧栏、搜索、总览、计数、推荐和科普均使用相同登记，不维护另一份专题菜单。

`app.js` 是任务路由的唯一激活者；`capabilities/task-selection.js` 将收藏、最近使用和启动偏好的页面 ID 解析为本次会话最近任务或登记中的默认任务。记忆只包含任务／专题、实际操作／原生变体及方向身份，输入、文件、参数及结果仍由原控制器持有。未登记路径进入工具目录。切换专题成员立即取消旧运算并作废结果，保留原输入、文件和各成员独立草稿；只有真实逆向对可转移语义兼容的具名参数。专题同属关系不等于参数同义或可逆。

本轮五组收拢保留真实实现边界：

| 专题 ID | 入口名称 | 实际成员与边界 |
| --- | --- | --- |
| `topic:base-family` | Base 家族编解码 | Base32／45／58／62／64／85／92 的真实编码、解码与 Base64 偏移检查；字母表和参数草稿各归原操作 |
| `topic:byte-numerals` | 数字与字节编解码 | Binary／Octal／Decimal／Hex、Hex Content／Hexdump、Float、BCD、通用 Base 与 Text-Integer 各保留原字节／数值约定，不按相似名称互换单位 |
| `topic:character-codes` | 字符编码与码点 | 原 ASCII、UTF-8 字节和 Unicode 码点原生控制器，保留各自进制、分隔与实际方向 |
| `topic:text-escapes` | 文字转义与还原 | 原反斜杠十六进制、Unicode、HTML 实体、URL 百分号转换，保留各语法和原操作身份 |
| `topic:qr` | 二维码与条形码工具 | ZXing 识别、QRazyBox／jsQR 矩阵修复、CyberChef 生成及识别四个实际成员；选择成员后激活其原表单与接口 |

`native:radix` 仍是对整个整数做进制换算的独立能力。例如整数 `256` 转十六进制为 `100`，不等于把文字 `256` 的 UTF-8 字节逐个转为十六进制；不能因名称都有“十进制／十六进制”就把两者视为同一算法。专题数量只描述导航入口，不代表算法减少或增加；全部 505 项原始 CyberChef 操作及来源归属保持完整。

`resolveCapability` 先校验原始 `op:`／配对别名、明确操作及成员 ID，再选择对应原生或 Chef 目标。`Generate QR Code` 和 `Parse QR Code` 的旧入口必须分别进入生成与识别成员，不能落回默认 ZXing 识别。混合成员不因共享专题就共享输入类型：图片识别使用文件／像素或原始字节，生成使用文字；原始文件与当前处理视图继续由素材所有者区分，只有用户显式“作为输入”或沿用图片动作才采纳结果。

验证范围遵循 [TESTING_POLICY.md](TESTING_POLICY.md)：日常只测受影响契约；本文列举的是保留的覆盖能力，不是每次改动的执行清单。完整检查使用 `npm run verify:all`。

本文记录正式工作台的信息结构和开发契约，与 [UI 开发强制规则](UI_DEVELOPMENT_RULES.md)、[通用 UI 组件](UI_COMPONENTS.md) 一起执行。功能数量从当前登记生成，旧工具页面数量不等于能力入口数量；本轮实际测试结果只以根目录 `VERIFICATION.md` 和本次报告为准。

大类用于回答“从哪里开始”，能力组用于说明“这里能做什么”。用户明确新增科普后，五类约定替代此前四类约定。分组名称、顺序、用途、代表入口和数量由统一登记产生，不允许首页、侧栏、搜索和任务选择各自维护分类表。跨类别相关能力通过关联入口连接，不复制运算引擎或资料快照。资料查询保留固定数据库与真实记录；科普解释这些工具涉及的知识，不替代查询或运算。

## 渐进浏览

- 分类总览同时展示全部能力组。每组直接列出能代表不同用途的少量入口，并显示真实总数；不能只展示第一种编码、默认算法或单一资料。
- “全部 N 项”在该组内展开完整紧凑列表，其他组继续可见。展开只改变浏览量，不改变分类、不跳转新的层级页面。
- 完整目录提供搜索、五类筛选和组索引。定位一个组或一个任务只需这一层；搜索默认覆盖五类，不随当前工作区偷偷缩小范围。
- 中文名称、英文原名、专业别名和玩家常用描述共享同一匹配模型。搜索、代表入口及完整列表必须到达同一个真实任务。
- 进入任务后，共享页头保留当前任务标题、收藏、相关科普、使用说明、返回能力组和全部功能入口；相关科普与使用说明放在同一个 `.heading-actions`。移除顶端分类面包屑、同组功能横排（peers）和壳层方向按钮；方向只由原表单的真实下拉框选择，参数／输入／结果仍归原控制器。

侧边栏是正式导航的一部分。桌面保留可收起的常驻侧栏；手机使用同一个侧栏节点的原生抽屉，不能重建控件或创建第二套目录。打开／关闭导航、变更宽度或访问网站页均不得清除工具的输入、文件和监听器。首页只保留已收藏、最近使用、工具导航。

侧栏大分类名称打开分类总览，旁边独立按钮只展开／收起分类。多工具组在侧栏内展开真实功能链接，不再跳转组总览；只有一项功能的组直接显示该工具。点击具体工具或科普条目一步进入真实工作区／正文。侧栏搜索直接显示按统一相关度排序的任务与文章，保留明确的编码／解码方向；清空搜索恢复原展开状态。长列表按需分批呈现，当前功能高亮采用能力 ID，不能把同一页面内的所有操作一起选中。旧组总览深链接继续兼容，但不作为侧栏具体条目的目标。

## 统一登记与兼容入口

`public/capabilities/registry.js` 将现有原生工具和 CyberChef 操作映射为可发现的能力记录。记录包含稳定 ID、所属组、中文名称、搜索别名、原始来源工具 ID／操作 ID、执行边界及相关能力。代表入口、计数、目录与搜索由这份记录派生；新工具先登记再组合页面。

非空搜索统一通过 `registry.js` 的 `searchEntries` 委托 `capabilities/search.js`：精确标题、名称、操作和明确方向优先，无直接匹配时再用固定本地 Fuse.js 7.5.0 查找近似拼写候选，各界面只负责展示上限和分类过滤。索引仅包含公开名称、别名及操作元数据，不索引或发送线索、文件、结果、笔记及偏好。不能只测试完整匹配集合存在，必须验证精确命中在真实展示范围中可发现。空查询继续采用库存顺序，不变更登记对象。

顶端查找由 `workspace.js` 在原位 `Input`／`SearchField` 中接收输入，候选在非模态浮层展开，不复制输入或打开另一张搜索弹窗。Ctrl／⌘+K 聚焦原输入；上下键选择、Enter 打开、Escape 与外部点击关闭；保留中文输入法的组合输入以及任务切换／卸载清理。完整目录保留独立的导航用途，不与顶端输入混为同一个弹窗流程。

CyberChef 完整处理链只登记一个可见的 `native:cyberchef`。原 10 个 `chain` 流程控制、新增 78 个配方专用操作与 5 个 `retained` 库存记录不进入可见目录、侧栏数量、推荐和独立科普；它们仍保留 `byOperation` 所有权、原操作 ID、配方参数和全部 505 项来源覆盖。新增 78 项为计算器／位逻辑／集合 26 项、网络报文／指纹／安全情报 24 项、开发编写／压缩／命名／模板 14 项、随机／UUID／占位／当前时间生成 7 项、密钥封装／签名格式 5 项、恶意软件分析 2 项。固定来源目录的 `sourceModes` 仍记录原始 489 task、1 existing、10 chain、5 retained，这是来源与适配器库存，不表示有 489 个公开工作区；公开范围先应用配方专用策略，再按专题合并后的登记计算。流程控制正文归入完整处理链的一篇文章，新增 78 项不各建科普，不通过删引擎内部操作来减少菜单。

登记必须检查唯一能力 ID、明确组归属、原始工具覆盖和每个上游操作唯一归属。缺项或多归属立即报错，不能默默塞进“其他”。上游目录的流程控制、保留或未开放快捷入口是来源清单的一部分，不能因覆盖统计而冒充可独立执行的工具；图片 OCR 等用户已删除入口继续保持删除。

旧 `#crypto`、`#encoding`、`#image` 等页面及 `#panel/group` 深链接仍指向原算法和参数；原始 CyberChef 操作名、参数值与配方格式保持不变。功能 ID 与兼容工具页面 ID 是不同身份：收藏、最近使用、启动偏好和设置导入／导出沿用受校验的稳定工具 ID，不因新能力名称丢失旧数据，不把私密输入塞进路由或偏好。

同类型已支持的加密／解密、编码／解码登记为一个功能族，在工作区明确选择真实方向。`operation-pairs.js` 是 `CHEF_OPERATION_PAIRS` 的唯一声明，由 registry 重新导出；原生转换在所属能力的 `nativeDirections` 登记。专题可包含多个这样的配对及非逆向操作，但专题本身 `reversible:false`，不能将签名／验签或哈希误称逆向。`byOperation` 让每个原始操作找到唯一能力所有者；`chef-tools/families.js` 投影真实操作，`chef-tools/inverse.js` 从唯一配对表派生反向映射。完整处理链仍能添加每个实际操作，配方、运行时与来源覆盖保留原始 ID。

`aliases` 将旧单向能力 ID 映射到统一能力及原操作／原生方向，所有路由入口通过 `resolveCapability` 校验。旧解码／解密链接必须打开原方向，明确方向的搜索也不能落回默认编码。原表单方向下拉框保留源输入，立即取消旧执行、作废结果，只转移兼容的具名参数，并保留各方向独有草稿；只有“作为输入”显式采纳真实字节与已执行操作／参数快照，之后再按需选择方向。删除顶端方向按钮不删除路由方向状态，不恢复独立的反向快捷按钮。进入明确逆向时按已采纳来源的输出／输入格式初始化目标输入／输出；普通输入不猜格式，外部采纳清除旧归属，用户后续编辑不重复初始化。不得按参数位置复制不同定义，不给哈希、统计、签名／验签和有损编辑推测逆向，也不承诺任意输入无损往返。

## 科普内容与关联

每项真实可见功能独立一篇，编码／解码功能族只需一篇，专题工作区只占一个科普入口。正文分片在 `public/knowledge/articles/`；`knowledge/topics.js` 根据真实专题成员做纯内容合并，`content.js` 校验稳定 ID、唯一 `capabilityIds`、机制段落、实例与文献。每个成员原有输入单位、具体映射／运算步骤、完整可复核实例、参数及边界都保留，文献 ID 重命名须同步重映射每节 `sourceIds`。禁止将专题合并变成删正文或按组补一篇泛概论；配方专用 78 项不独立登记科普。资料查询也解释该功能的编码／结构／读法。

每节 `sourceIds` 引用文章局部 `sources`，来源包含真实 URL、机构、文献标题、章节、语言与资料性质。先找国内官方中文文档及国内原始标准镜像；仅有原文则标注语言。引用必须支持对应细节，不能仅贴泛文档首页。原始实现与公开标准可能不同，需按固定版本核对，不把上游简介的错误当规范。具体要求见 [科普内容规则](KNOWLEDGE_CONTENT_RULES.md)。

登记根据文章 `capabilityIds` 建立每项功能唯一的 `learningIds`；错组、不存在的功能、重复覆盖和缺文章都直接报错。`relatedIds` 解析真实目标及原工具方向别名。旧分组科普及其 `learn:<旧文章ID>` 兼容映射已按用户要求删除；只登记逐功能文章，标题只用基本名称。文章链接为 `#knowledge?task=learn:<articleId>`。

阅读页同一文档挂载 `#panel-knowledge`。目录提供正文／文献搜索、四个工具领域与主题筛选，目录与正文在所有屏幕宽度分别占满工作区，返回目录保留筛选条件并恢复焦点；ReferenceList 在文章末尾集中列出全部文献，小节 sourceIds 仍保留依据归属。重入同篇保持原节点，异步关联校验修订号并在取消／销毁后拒绝旧回调。阅读目录不采集用户输入，不以示例代替用户结果。

文献引用与软件依赖分别管理：引用标准／文档并不意味着集成其代码，也不生成浏览器 API 或本站仓库的虚构依赖页脚。实际复制的第三方文字、数据或图像须遵守具体许可；原查询工具和已集成引擎的许可与出处继续保留。

## 各类工作区的数据归属

| 工作区 | 共享内容 | 独立保留的模型 |
| --- | --- | --- |
| 文本／编码／密码 | 用户明确提供的文字或原始字节、兼容参数、真实方向 | 各操作参数定义、输入格式、输出类型与限额 |
| 国家／货币／交通 | 已选择的国家／地区对象及相关查询上下文 | 每个资料库的精确记录 ID、筛选、分页和固定资料范围 |
| 天体／观测 | 真实目录对象，以及用户设置的时间与地点 | 目录固定坐标和 Astronomy Engine 观测计算；无坐标对象不得伪造零值 |
| 其他资料 | 可视索引／目录与一个当前详情 | 卦象、牌面版本、字符码点及年代层级 |
| 图片／音视频／文件 | 当前用户素材、文件属性、当前预览与明确后续处理对象 | 原始文件和处理结果分离；照片隐写不能被重编码预览覆盖；本机 CIF 在原模型上传流程解析 |
| 棋谱／网格／模拟 | 公共标题、状态、工具栏、视图布局与导航 | 围棋和国际象棋规则、题型约束、生命游戏、魔方、图灵机及各自撤销／单步模型 |
| 科普阅读 | 统一主题组、搜索、文章与关联能力 ID | 有原始依据的逐功能正文、阅读选择及焦点；不采集工具输入或把科普示例当作用户结果 |

资料页应使用适合资料的图形或索引浏览，点选显示当前真实记录，并从同一个记录模型进入关联操作；不要把所有资料强制转成同一种输入表单。现有三维观察的上传入口直接解析本机 CIF，不提供晶体样本目录或跨资料面板的上传桥接。详情、完整结果和后续任务来自当前查询对象，不能留下另一个旧对象的成功状态。

资料检索必须基于完整选定标准／目录的固定快照，先核查原始条目和导入条件，再决定名称与范围；不把人工精选、少量样本或演示数据包装成同用途完整资料库。OEIS 272 条精选、COD 14 份样本、HYG 9,026 条筛选恒星、56 条精选 RFC 和手工 x86 指令／寄存器参考已退役：生成器、运行文件、任务、导航、关联与对应科普全部移除，原始来源与许可仅在 `upstream/` 归档。`#sky` 名称为“深空天体目录”，保留完整固定 OpenNGC 主表及补充表 14,034 条记录；国家／交通／Unicode 等完整选定资料集与真实天文、数论、反汇编计算保留。不能仅隐藏旧界面或将归档误登记为当前运行依赖。需要更广数据库检索的用途以明确说明和外站链接整理，不自动上传玩家线索。

Alpertron 当前只启用 `integer` 的整数表达式、素性检验、因数分解、除数和批处理。高斯整数、丢番图方程、离散对数、二次同余、平方和、立方和、两平方与奇数幂、二次无理数连分数、多项式分解求根的独立任务、参数协议、面板、联动和科普已退役；原官方 WASM、完整源代码和许可作为历史来源保留，不能由归档清单重新生成任务。基础进制、单位、通用计算及整数因子验证不受此清理影响。

输入归属于原控制器或素材模型，公共任务外壳只连接与移动原节点。换任务可以保留适用的输入；旧结果、执行状态和异步回调必须按任务修订号作废。下载、复制和继续处理仅使用当前真实结果，不能从截断预览、展示 HTML 或格式化文本重建二进制数据。

`createInputSession()` 通过原控制器的读取／采纳接口共享适用输入，保留源类型：十六进制和 Base64 编辑内容不能冒充普通 Unicode 文字，文件与明确续接的原始字节不能自动解码。原生转换仍受自己的输入限额约束。媒体 `getMaterial(kind, source)` 的读取在异步导出前后校验原素材与修订号；切任务只选择控件，不能悄悄把预览替换为原文件。

二维码修复仍通过显式 `arg:qr-source` 接收原图或当前视图的 Canvas，保存原矩阵、撤销和图片草稿。离开实际修复成员时同步终止 Worker、清理计时器及解码候选，图片读取以独立代次拒绝迟到回填；重新进入不能收到上次任务的成功或错误。ZXing 的不可中断 WASM 调用使用逻辑失效而非假报停止内部运算。app 将 `beginBarcode: imageTools.beginExternalTextResult` 注入识别控制器，识别器通过 `{isCurrent, publish, clear}` 租约提交统一图片结果模型，因此正文、复制下载、笔记和图稿动作使用同一份真实当前结果。更换来源、视图、原图或成员均同步失效，卸载清理监听和资源。

实际成员激活后，app 发布只含页面、能力／成员、操作和实现种类的 `arg:tasksourceschange`，由 `project-sources.js` 刷新末尾来源；事件不携带文件、参数值或结果。共享来源所有者持有组装完成后的面板来源基线，混合成员按实际实现收窄，返回原生工具或重新挂载时恢复正确基线，不能把上次已收窄的二维码或 Chef 页脚当成整张图片工作区的原始来源。生成格式 PNG／SVG／EPS／PDF 继续下载真实字节，显示 HTML 与预览不是来源文件或可重新识别的原始输入。

载入引擎与载入目录也属于异步任务。深链接载入失败必须显示可见的恢复入口，不能让所有页面隐藏后只留下未捕获异常。处理链 `openRecipe` 在等待引擎后检查请求归属、输入／配方修订和当前路由；已离开任务或出现更新编辑的旧请求不得回填内容或抢回导航。分类任务使用原地载入方式保留当前能力路由。

科学与资料查询通过共享 `mountTaskLifecycle` 登记取消、超时清理和卸载行为。同页面的任务身份变化也必须作废旧输出；关联资料预选只能在实际目标页面进入后启动，不能在隐藏页面提前计算。保留原输入与对象上下文，使用修订号拒绝已排队的旧回调。

## 组件、动效与生命周期

页面只从 `public/ui/index.js` 使用公共组件与控制器；共享任务外壳也是组件组合，不能绕过工厂或写第二套控件。公共外观与动效只由 `ui/components.css`／`ui/motion.js` 拥有。地图、棋盘和 Canvas 等专用图形仍属于工具渲染层。

桌面按可用宽度提供输入／结果或浏览／详情的并排布局；手机自然堆叠，正文不裁切，内部长表格有界滚动，操作可触达。所有正常操作目标至少 44px，搜索与弹窗适配键盘可见视口，键盘操作和焦点顺序完整。

动效必须可中断、支持实时减少动态效果；状态、焦点、取消和输入作废立即完成。连续搜索、拖动、运算进度不反复播放进入，不克隆私密内容作退出动画。原生弹窗关闭同步恢复焦点；搬动侧栏或工具节点不丢文件，确实卸载时清理 Worker、事件、观察器和动画。

## 隐私、来源与验收

正常运算继续本地执行，重构导航不会添加上传、外部嵌入或远程执行依赖。仅用户明确选择的 HTTP／DNS 等联网操作发起对应请求。各任务使用原引擎、原限额、超时、取消与失败恢复，不能为统一 UI 降低边界。

中文使用说明放在共享帮助区；工作区保留真实状态和必要的数据限制。实际第三方项目、数据和素材的具体用途、链接及精确许可证在工具页最后呈现，关于页保留完整登记；纯本站代码、浏览器接口和空来源栏不展示。移动或合并任务时不能丢失来源归属。

新增回归登记到测试映射及 `npm run verify:all`，至少验证统一登记无缺项／重复、五类全局搜索、每组就地展开、旧深链接／收藏／偏好兼容、侧栏／抽屉、真实任务输出、跨任务输入与结果作废、资料详情联动、原始媒体保留、正常／减少动态效果、键盘和多端布局。功能族验证逐项操作覆盖、旧方向别名、双向实际运算、具名参数及源输入保留；科普验证逐功能唯一覆盖、正文演算、逐节文献、安全链接及精确关联能力、阅读焦点和过期回调拒绝。固定上游摘要先验后构建；已有引擎、许可、安全与隐私回归保留并按实际影响选择。只有本轮实际运行可以写入通过记录，原型示例和浏览器模拟不能代替生产运算或实体设备验收。

## 原生文件编辑与 IT 固定资料

十六进制编辑登记为 `native:hex-editor`，属于 media/files；继续使用 `#panel-file` 和唯一 `#file-input`。公共上传、统计和加载状态是文件所有者，分析／编辑视图仅选择同一素材，不能复制上传节点或把错误藏进未选中的视图。编辑器的原始／工作字节与文件分析素材分离，只有用户明确采纳时才交接快照；交接验证操作归属、路由和文件代次，不重新异步读取人工 File。离页立即停止搜索，恢复视图保留内存修改，卸载释放全部缓冲。

IT 查询登记为 reference/technical 的四项原生能力：端口／协议、HTTP、MIME／字符集、域名／公共后缀，同一 `#it-reference` 通过可见标签展示资料类别。标签选择同步真实能力深链接和页头，内部范围筛选由数据的 group 派生，不能重新维护一份资料类别清单。原始来源在 upstream/it-reference，离线生成先验证保留的固定哈希；派生运行文件与许可声明纳入完整性审计。完整选定 IANA、mime-db 和 PSL 资料继续提供真实记录；精选 RFC 和手工指令参考不再生成或提供任务，相关标准作为文献引用时不能冒称集成依赖。普通构建不联网。

输入／输出格式在双向算法中分别描述明文侧与密文侧，是方向独有参数；同名、同类型不代表同语义。普通切换保留目标方向的草稿或真实默认值，Key／IV／Mode 等相同角色参数才共享。显式结果采纳的格式初始化使用已执行快照，不能用未采纳的预览或当前参数推断。回归必须覆盖首次加密／解密默认格式、目标手改格式往返保留，以及 Unicode 结果续接的独立密文与原字节对照。
