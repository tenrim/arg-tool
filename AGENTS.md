# Instructions for Codex

## Standalone source distribution (user-approved 2026-10-15)

- This worktree owns `codex/open-source`, an independent-history source distribution. The server deployment worktree remains on main. Do not merge main wholesale or merge this branch back; port scoped original changes and tests.
- Third-party runtime/source/data/font payloads are automatically downloaded from the pinned public release using scripts/source-dependencies.py and dependencies.lock.json (npm run setup); the separately delivered ZIP remains an offline option. Keep payloads ignored and outside source Git history; preserve original adapters, patches, metadata and license notices. Do not publish the local full-history backup branch.
- About content is generic with author attribution; personal support/related-site promotion and the Sites project binding are removed. Feedback defaults to local copy/download. Optional same-origin mail service is explicitly configured by each operator in public/deployment.js; never add credentials to frontend files.
- These distribution choices supersede older server-specific branding/about/deployment guidance below. Keep tool behavior, safety and scoped-verification contracts.

- Native conversions and CyberChef single-operation tasks share `ConversionLayout`: direction/parameters/actions above, input and result cards below. Use a direction select; remove the duplicate task heading and keep operation guidance in the shared heading's 使用说明.

## Change-scoped verification (user-approved 2026-10-13)

- Read [docs/TESTING_POLICY.md](docs/TESTING_POLICY.md) and [docs/MODULE_BOUNDARIES.md](docs/MODULE_BOUNDARIES.md). This workflow replaces the former blanket full-verification requirements. Run only checks affected by the current change; do not run unrelated engines because a shell, catalogue or shared UI file changed.
- Start with `npm run test:plan -- --files <all files changed in this task>`; review reasons, then `npm run verify -- --files <same files>`. Without --files the runner includes all staged, unstaged and untracked changes; use --base for branch/CI comparisons. Do not include earlier, already-verified work just to repeat it. Unknown code paths must receive a test owner instead of being silently skipped.
- `npm test` selects affected units; `npm run check` selects affected static checks. `npm run verify` already includes both: do not run all three in succession. No automatic whole-site build for ordinary UI/logic changes; build when the generator, packaging or actual dist delivery is affected.
- `npm run verify:all` is the explicit full-release/whole-project command. Preserve the full suite catalogue and its assertions, but do not run it merely because shared code changed. PC/phone, keyboard and normal/reduced motion remain in the relevant UI suites. Report actual scope and results; after a failure rerun only the failed/affected checks unless new changes justify more.
- `npm run audit:architecture` enforces literal module boundaries and cycle freedom. Discovery metadata must not depend on UI, models or algorithms; UI components never import feature controllers; cross-feature edges require named bridge contracts. Runtime Worker/event/DOM bridges also need owner and behavior coverage; a static graph is not a complete runtime proof.
